## SIM-03: shutdown 조건과 실제 원인

근거는 pinned source `python_backend.py`의 `_tefunc` 약 1158–1176행 및 `is_shutdown` 약 1388–1407행이다.
문턱은 원자로 압력 3000 kPa gauge 초과, 원자로 온도 175°C 초과, 원자로 체적 2–24m³ 밖, 분리기 체적 1–12m³ 밖, 탈거기 체적 1–8m³ 밖이다. **체적 문턱을 측정 level(%) 문턱으로 읽으면 안 된다.**
내부 물리 상태를 검사하는 종료와, 잡음이 더해진 압력·온도 측정값을 검사하는 종료가 함께 존재한다. 경계값은 엄격한 부등호이다. 이는 구현의 종료 규칙이며 이번 연구의 Safety 임계값을 확정한 것이 아니다.

수동 모드, 동일 초기 상태·시드, 600초에 XMV10을 41.10581288%에서 42.10581288%로 올렸다. 기준 실행도 같은 수동 모드이다. 명령은 1 percentage point이며 상대 1%가 아니다.

| 관측 잡음 | dt(초) | 종료 상태 시각 | 종료 평가 시각 | 내부 압력(kPa) | 판정 |
|---|---:|---:|---:|---:|---|
| 원본 | 1 | 1788 | 1787 | 3000.574119 | 내부 압력 초과 |
| 원본 | 0.5 | 1786.5 | 1786 | 3000.182041 | 내부 압력 초과 |
| 원본 | 0.25 | 1785.75 | 1785.5 | 2999.986000 | 측정 압력 3000.340513으로 wrapper 종료; 내부 shutdown은 false |
| 표준편차 0 진단 | 1 | 1788 | 1787 | 3000.574119 | 내부 압력 초과 |

최초 접근 기록은 상태 1614초/평가 1613초에서 압력 2850.532046 kPa이다. 이는 미리 정한 압력 문턱의 95% 접근 기록이며 모든 가능한 물리적 접근의 전수 판정은 아니다. 최초 실제 압력 초과 시점은 위 종료 평가 시각이다.
dt=1 종료 시 온도 89.982207°C, 원자로 체적 16.010097m³, 분리기 3.881077m³, 탈거기 4.330211m³로 다른 종료 문턱 안에 있다. 상태·미분은 유한했고 solver의 비유한값 실패는 없었다. 마지막 내부 yy와 종료 부근 매초 원시 로그도 보존했다.

**원인 분류: 기존 1788초 종료는 B(후보의 공정 제한 조건에 따른 shutdown).**
0.25초 원본 잡음 실행에는 측정 잡음에 의한 조기 문턱 통과도 있다. 정확한 한계 도달 시각에는 적분 오차와 종료 검사 이산화가 영향을 준다. 실제 TEP가 같은 시각·같은 방식으로 종료한다고 확정하지 않는다.

### 적분 민감도와 반응

`simulator.py`의 `step()`가 실제 `sim.dt`를 사용함을 확인한 뒤 1/0.5/0.25초를 설정했다.
제어기 내부 dt는 별도이므로 이번 적분 간격 비교는 **수동 모드에 한정**했다. 폐루프 controller의 시간 기준까지 함께 바꾸는 실험은 NOT_RUN이다.
step 변경은 RNG 소비 횟수도 바꾼다. 이를 분리하려고 `_teproc.xns` 표준편차만 실행 중 0으로 설정한 진단을 별도로 수행했다. 소스 수정·Fault 주입·값 맞춤은 없다. RNG 자체를 동일 경로라고 주장하지 않는다.

관측 시계 0..1770초, 30초 간격 60개 공통 시점에서 비교한 최대 차이는 다음과 같다.

| +1 pp 조건 | 1 대 0.5초 | 0.5 대 0.25초 |
|---|---:|---:|
| 원자로 압력(kPa) | 0.647860 | 0.324432 |
| 원자로 온도(°C) | 0.052131 | 0.026078 |
| 원자로 level(%p) | 0.004060 | 0.002030 |

상태 시계에서 yy 최대 절대 차이는 0.034736→0.017385로 감소했으나 서로 다른 단위의 상태를 한 값으로 합친 진단값이므로 물리적 오차 한계로 해석하지 않는다.
잡음 통제 조건에서 평가 1770초의 개입-minus-기준 온도는 dt 1/0.5/0.25초 각각 -28.801948/-28.854078/-28.880156°C, 압력은 +277.726203/+278.374056/+278.698485 kPa이다. 이것은 해당 수동 정책·초기점의 후보 내부 반응이며 SCM 효과 검증 또는 안전한 복구가 아니다.
온도 감소만으로 인과 메커니즘 검증을 선언하지 않는다. 폐루프 기준과 수동 개입을 섞지 않는다.

오차 감소는 이 조건·기간에서 Euler의 수렴 경향과 일관된다. 세 간격·단일 시드만으로 전 구간 안정성이나 모델 정확성을 보장하지 않는다.
독립 Fortran 비교는 **NOT_RUN**: backend가 사용 불가이고 gfortran/flang/cl 실행 명령이 없다. 별도 모델·controller 동등성 확인도 필요하다. 다른 구현을 임의 정답으로 삼지 않았다.

## SIM-04: 초기화 계약

수동/폐루프 각각 새 객체 두 개, 즉시 재초기화, 60초 운전 후 초기화, IDV4 600초 주입→해제→초기화를 수행했다. 초기 스냅샷과 이후 60초 경로를 저장했다.

| 구성 요소 | 관측 결과 |
|---|---|
| simulation time / step count | 0 복원 |
| yy 50개 / XMV / IDV / RNG `_g` | 초기화 후 fresh와 정확 일치 |
| controller(설정·적분/이전 오차 포함) | 새 controller로 초기화, 저장된 내부 값 일치 |
| walk block / valve 관련 cache | 저장된 상태 복원; valve state는 yy 및 cache 비교에 포함 |
| 측정값 | 운전·Fault 후 reset에서는 최대 약 1.36e-12 초기 차이 |
| 열역학·stream cache | 작은 차이가 잔존; 일부 약 3e-11 수준 |

`initialize()`는 전체 `TEProcBlock`을 새로 만들지 않는다. 온도 계산 `_tesub2`는 남아 있는 온도를 Newton 초기 추정값으로 사용한다(`python_backend.py` 약 391–423, 862–866행). 관측된 차이는 이 cache/warm-start 재계산의 부동소수점 민감도와 일관된다. RNG나 yy의 미복원 증거는 없다. 모든 메모리 상태의 동일성 또는 유일한 원인까지 입증한 것은 아니다.

짧은 경로에서 같은 객체 reset의 측정 최대 차이는 1.82e-12, yy는 9.31e-13 이하였다. 첫 진단 뒤 보고용으로 정한 atol=1e-9/rtol=1e-12 안이지만 **비트 단위로는 불일치**한다. 사전에 등록한 성능 합격 기준처럼 표현하지 않는다.
새 객체 fresh1/fresh2와 즉시 initialize 반복은 각 모드에서 저장된 경로가 정확히 일치했다.

**공식 후속 실험 계약: 매 반복마다 새 `TEPSimulator` 객체 + 동일 source/backend/seed/control mode + initialize.**
같은 객체의 reset은 탐색용 허용오차 재현과 구분한다. 관측값·상태·RNG를 강제로 맞추거나 원본 함수를 고치지 않았다.

## COMPAT-01: 단계별 호환성

[benchmark 논문 IV-A/Table II·III](https://arxiv.org/html/2208.01529#S4.SS1)는 정상 데이터, 원측정 0.1Hz, 75시간에 걸친 3분 sliding median 및 최종 3분 빈도를 보고한다. upstream [Manca 데이터 DOI](https://doi.org/10.21227/326k-qr90)는 확인했으나 이번 도구에서 Dataport 페이지 접근은 HTTP 오류로 실패했다. 원자료와 현 CSV의 행별 timestamp·전처리 코드·정확한 제어기 계보는 회수하지 못했다.

현재 CSV의 검증된 1499×31 입력을 그대로 사용했다. 기존 공식 공개 파일 동일성과 시간순 중간 수준 판정은 기존 freeze를 유지한다. 논문 1500 samples와의 차이는 원인 미확정 경고이며 row를 추가하지 않았다.

| 수준 | 판정 | 근거와 한계 |
|---|---|---|
| 1. 이름·선언 단위·순서 | 대응 확인 | X1..22→XMEAS1..22, X23..33→XMV1..11; X27/MV5·X31/MV9 제외. 단위 표기는 일치하나 값의 scale 동등성까지 보증하지 않음 |
| 2. 정상 분포·범위 | 차이 확인, 동등성 미확인 | 새 폐루프 정상 7200초 성공, 관측 시계 30초 격자 240점. 31개 변수 기술통계 CSV 저장 |
| 3. 모델·제어기 | UNVERIFIED | 후보는 50상태·41측정·12MV 및 분산 PI/일부 cascade 구조. 기존 원자료의 동일 controller/운전점/revision 근거 없음 |
| 4. 개입 기제 | UNVERIFIED | manual XMV 직접 명령은 실행됨. 기존 폐루프의 설정값·override 개입과 동등하지 않음 |
| 5. 효과 비교 정답 | NO-GO(직접 사용) | 이름 일치·정상 상관·GT 구조로 효과 정답을 만들 수 없음 |

`variable_compatibility.csv`는 source 선언 단위와 benchmark 표의 대응을 기록한다. 압력은 gauge이며, XMV %는 밸브/조작 명령이지 유량의 실제 물리 단위가 아니다. 후보에는 기존 분석에서 빠진 MV5/MV9/MV12 및 조성 측정 23..41이 남아 있어 제어·상태 전파에 영향을 줄 수 있다.

2시간 기록을 3분 비중첩 창(30초 관측 6개)의 중앙값 40개로 요약한 **진단용 근사**도 작성했다. 0.1Hz 원자료의 sliding median 파이프라인 재현이 아니며 warmup 제외나 운전점 보정은 하지 않았다.

| 변수 | benchmark 평균 | 후보 30초 관측 평균 | 설명 |
|---|---:|---:|---|
| 원자로 압력 X7(kPa gauge) | 2800.002156 | 2708.451115 | 운전점 차이 |
| 원자로 level X8(%) | 65.004262 | 74.920368 | 운전점 차이 |
| 원자로 온도 X9(°C) | 122.900131 | 120.401024 | 운전점 차이 |
| 냉각수 조작 X32(%) | 35.946906 | 41.055246 | 제어 출력 차이 |

X19 등에는 훨씬 큰 scale 차이도 있다. 단위 선언이 같다는 이유로 수치를 임의 변환하거나 controller를 맞추지 않았다. 분포 차이를 순전히 모델 방정식 오류라고 단정하지 않는다. 기록 기간·집계·잡음·운전점·제어 정책이 함께 다르다. p-value·독립 표본 주장·새 Safety 기준을 만들지 않았다.

최종 호환성 분류는 **다른/미확인 공정 설정을 포함한 제한적 탐색 실험**이다. 직접 비교를 하려면 원자료 생성 설정과 제어기, 단위/scale, 집계 및 개입 기제를 별도로 검증해야 한다. 현재 31변수·28간선 GT는 구조 참조이고 후보의 효과 정답이 아니다.

## 실행·검증·다음 기준

재현 명령과 파일 계보는 `experiments/simulator/diagnostics/README.md`에 있다. 외부 source가 필요한 실험과 source 없이 raw evidence를 검사하는 CI를 분리했다. 모든 데이터 hash·기존 그래프·Step 6 결과는 기존 검증 절차로 재검사한다. 이번 작업에 새로운 인과발견/SCM fitting/Recovery·Safety 계산은 없다.

다음 우선순위:
1. COMPAT-01: 원자료 생성 controller/운전점/scale·집계 근거를 확보하고 일치 가능한 범위를 문서화. 근거 없으면 외부 전이 실험으로 사전 분리.
2. SIM-03: 같은 방정식·초기점·controller를 가진 독립 기준 구현의 실행환경 확보 후 동일 시점 비교. 폐루프 dt 변경은 controller 시간 계약 검증 후 수행.
3. SRC-01: frozen 생성 코드의 정확한 원본 회수. 현재 설정으로 새로 작성한 코드를 과거 Final 코드라고 취급하지 않음.

복구 과제와 안전성 평가는 이 선결 조건 뒤 사전 확정한다. main 자동 병합은 수행하지 않는다.
