# TEP Studio 실행과 생성환경 검증

2026-10-29. 판정 **TEP_RECONSTRUCTION_PROMISING**. 공식 보관본과 공정 C 코드·헤더·초기 상태 3개가 같고, 고정 TEP Studio의 실제 공정 계산이 격리 Linux에서 2시간까지 실행됐다. 반면 원본 관측자료의 생성 계보와 제어·시계·잡음·전처리 계약, 28간선의 완전성은 확보되지 않았다. 기존 7개 그래프의 점수를 이 실행의 개입 결과와 결합할 수 없다. 이는 전체 환경이 서로 다르다는 증명도 아니다.

## 실제 수행과 출처

[공식 모델](https://depts.washington.edu/control/LARRY/TE/download.html), [고정 Studio 소스](https://github.com/khalidlabs/tep-studio/tree/852f0c69ab974540750d61bd1dbfafd56bfd80bb). 세 파일 외 제어기와 초기 기억까지 동일하다는 뜻이 아니다.

Windows에서는 C 컴파일러와 사용 가능한 WSL 배포판을 찾지 못했다. 시스템에 설치하지 않고 [격리 Linux 실행 기록](https://github.com/5castlemin/tep-causal-decision-reliability/actions/runs/40873474299)에서 GCC 13.3.0과 Python 3.11로 외부 고정 커밋을 빌드했고 C 확장 import, 초기화 및 폐루프 계산을 수행했다. 전체 여섯 시험에서 공정 종료와 비유한 측정·명령은 없었다. 시험 프로세스 wall 2.26초, 최고 메모리 176684 KiB는 설치를 제외한다. Python의 정확한 patch 버전과 설치 전체 자원은 기록하지 못했다. 원시 결과는 Git 제외 `data/local/tep_studio_execution/run_40873474299/`, 실행 artifact의 SHA-256은 `8d9e6091560d27a4c0ccf5abf3a36946b6422371585dee9dbe9ccb5f9eb38899`; artifact 보관 기간은 GitHub 정책에 따른다. 원본 CSV SHA는 `52ae445b4355201db9591822282381c8de861afe49bdbc9452db08b01e7d3711`.

사전에 `EXPERIMENT_PLAN.json`을 커밋했다. seed 465120799, 고장 없는 기본 외란, 제어 주기와 RK4 간격 각각 0.0005시간(1.8초), fresh 공정, 0.1665·0.5·2시간 순이다. 10분 아래 시험부터 시행했고 매 단계 종료·비유한값이면 중단하도록 했다. A는 초기 측정값으로 모든 목표를 설정하는 기본 제어기, B는 같은 초기화 후 압력·액위·온도 목표만 각각 2800 kPa·65%·122.9°C로 설정한다. 공식 모델 전체 제어기 재현이 아니다. 외란 override는 기본 비활성이다. 동일 seed의 반복은 독립 반복 검증이 아니며 이번에는 별도 반복을 실행하지 않았다.

## 실제 관측: 원본과 시험 비교

| 값 | 원본 1499행 평균 | A 2시간 평균 / 마지막 | B 2시간 평균 / 마지막 |
|---|---:|---:|---:|
| 압력 X7 kPa | 2800.002 | 2705.967 / 2705.557 | 2615.105 / 2634.588 |
| 액위 X8 % | 65.004 | 74.624 / 74.634 | 62.325 / 61.016 |
| 온도 X9 °C | 122.900 | 120.399 / 120.400 | 122.893 / 122.885 |

B에서 온도 평균은 가까우나 압력과 액위는 가깝지 않다. 2시간 평균에는 시작 직후의 과도 변화가 포함되고 B의 마지막 압력·액위도 움직인다. 수렴 판정이나 장기 정상상태 차이로 확정할 근거는 없다. A의 압력은 초기 목표 근처에서 유지되었으나 75시간 안정성이나 원본과 다른 정상상태가 확정된 것은 아니다.

`COMPARISON_31.csv`에 원본과 A/B 원시 시계열의 평균·표준편차·중앙값·5/95 분위수·첫/마지막 값·1시차 자기상관을 적었다. `RUN_SUMMARY.json`에는 31변수 상관행렬과 단계별 수치를 기록했다. 절대 평균 차이가 가장 큰 후보는 A/B 모두 X16(각각 -229.2/-331.0, 잠정 stripper pressure)이다. 서로 단위가 다른 변수의 절대 차이 순위는 중요도 순위가 아니고, X19도 약 228/217 차이나 잠정 XMEAS19 매핑의 원본 단위·의미가 미확정이다. 변수 대응을 확인하기 전 이 차이를 공정 오류로 해석하지 않는다. `VARIABLE_MAPPING.csv`는 이름과 단위의 후보 대응이며 원본의 export와 단위를 검증한 정답 대응표가 아니다. 구현 명령과 물리 밸브 상태는 다르므로 CSV의 XMV는 clamp된 제어 명령 후보로만 사용했다.

원본은 0.1Hz, 3분 이동 중앙값, 약 75시간으로 **문헌에서 보고**되나 창 경계·stride와 1499행 생성 코드는 미확인이다. Studio는 1.8초 간격 결과를 기록한다. CSV에 nearest 10초 샘플과 18개 후행 중앙값을 가정한 별도 근사 통계도 제공하나, 이는 원본 전처리의 재현이 아니다. 원본과 2시간 원시/가공 통계의 동등성 검정은 하지 않았다. 원본 시간 인덱스와 실제 센서 sample-and-hold 시간은 미확인이다.

## 제어·수치 방법과 남은 원인

공식 `MultiLoop_mode1.mdl`은 `ode45`·상대 허용오차 1e-6, Studio 기본은 고정 간격 RK4이다. Studio `registry.py`는 압력·액위·온도의 PI 및 포화값을 기록하나 공식 블록 전체와 계수·부호·기억·순서의 일대일 동일성은 확인하지 않았다. 기본 목표는 Mode1 측정값에서 구성돼 실제 A는 약 2705 kPa·75%·120.4°C다. 제어기는 초기 측정값과 명목 출력으로 내부 기억을 세팅하고 느린 생산·조성 목표를 ramp하며, 측정→명령 계산→0~100 제한→적분→끝 시각 출력 순으로 실행한다. 압력은 비율 제어를 통해 조작되며 단일 밸브 직접 조작이 아니다. Studio의 조성 기능 기본 활성, %G feedback 및 override 기본 비활성은 문헌 자료의 실제 사용 여부와 별개다. 공식 Manca의 MV5/MV9 폐쇄, MV12=100이 이 시험에서 같은 제어 계약인지 검증하지 못했다.

차이의 원인은 특정하지 못했다. 초기 상태 파일 동일성은 확인됐지만 실행 당시 원본의 사용 여부는 미확인이다. 목표값과 적분 방식의 차이는 코드로 확인했고, PI 계수·제어기 기억·순서·포화·보호, 교란/잡음 및 난수·센서 시계·전처리의 효과는 개별적으로 식별하지 않았다. B는 목표 세 개를 함께 바꾼 진단으로 원인을 하나로 분리하는 시험이 아니다. 결과에 맞춰 목표를 조정하지 않았다. 6·24·75시간, 새로운 개입·고장·복구·안전 시험은 실시하지 않았다.

## 연구 계약과 다음 행동

기존 28개 참조 간선은 벤치마크의 공정 지식 기반 평가 참조이며 비간선의 완전성, 센서·내부 상태·시간 지연 및 제어 피드백을 포함한 정적 직접 간선 의미는 검증되지 않았다. 원본과 이 환경의 관측/제어 정합성이 입증되지 않은 상태에서 새 개입 결과를 7개 그래프의 기존 F1과 결합하지 않는다. 공식 모델 복원과 TEP Studio는 유력한 동일 계열 후보이므로 복원은 계속하되, 연구 준비 완료 또는 실제 제조 성능 입증으로 판단하지 않는다.

**다음 하나의 작업:** 공식 MATLAB/Simulink 모델을 실행할 수 있는 환경 또는 동일 조건에서 기록된 공식 trajectory를 확보한 뒤, 같은 초기 상태·고정 입력·시계에 대한 짧은 공정/제어기 trace를 TEP Studio와 대응 비교한다. 입력은 공식 ZIP, 이 저장소의 고정 Studio 소스·계획·원시 기록이며, 완료 조건은 변수·단위·제어기 메모리·계산 순서를 맞춘 비교와 불일치 원인의 범위를 기록하는 것이다. 공식 trace와 라이선스 환경이 없으면 수행 불가로 남긴다. 이후에야 원본 잡음·전처리, 참조 간선 검증과 독립 개입 가능성을 각각 평가한다.

재현: `python scripts/check_tep_studio_source_hashes.py <archive_manufacturing 경로>`; Linux workflow `.github/workflows/tep_studio_probe.yml`과 `scripts/run_tep_studio_execution_probe.py`; `python scripts/compare_tep_studio_observations.py <고정 Studio schema.py> <압축을 푼 원시 기록 디렉터리>`. 원본 CSV는 Git에서 제외되어 별도 접근이 필요하다. 실행 환경 재현에 사용할 의존성 목록은 `BUILD_RESULT.json`에 기록했고 외부 패키지 버전 범위가 고정되지 않아 bitwise 재현은 보장되지 않는다.
