# Manca 원본 자료 확보와 데이터 복원

2026-10-30. **ORIGINAL_DATA_PROVENANCE_PARTIAL**. 최초에는 인증이 필요해 접근이 막혔지만, 사용자가 공식 IEEE 페이지에서 정상 원본 ZIP을 내려받아 제공했다. 이후 직접 압축 내용과 모든 파일 해시를 검증했다. 원본은 확보됐으며 현재 CSV의 정확한 가공 과정은 아직 재현하지 못했다.

ZIP SHA-256 `3585896933bd11a2ceea4c0c6c4521b3cc08a95491ddf3c4b5fbfbabac5b3938`, 압축64,881,474바이트, 내부66,257,101바이트. 정상 실행 세 개의 SIMOUT.xlsx(27001×73), XMV.xlsx(27001×12), TOUT.xlsx(27001×1), seed 텍스트가 있다. 원시 자료는0~75시간의10초 간격이다. seed는 기본값,24121989,12101992. 최초 센서41개와 실제 고정 명령0/0/100을 확인했다. 추출한 수치 배열은 Git 제외 `data/local/tep_original_data_recovery/normal_1.npz` 등이고 원본 Excel은 읽기 전용으로 처리했다. 파일별 해시·구성은 RAW_MANIFEST.json에 있다. 로컬 V1_2 기술보고서도 보존했다.

현재 CSV는 CPCaD-Bench commit72b0f5e3d14192478186ee0dc4338b7448087789의 CSV와 바이트 일치한다. SHA-256 `52ae445b4355201db9591822282381c8de861afe49bdbc9452db08b01e7d3711`; upstream NumPy 파일도1499×31이고 수치 차이는 최대9.1e-13이다. 이 공개 저장소에서 원본 전처리 실행 코드는 찾지 못했다.

문헌의3분 중앙값과 원본10초 기록을 근거로, 세 원본에서18개씩 비중첩 중앙값·시작행0/1·첫블록제외0/1의 총12가지 **탐색적** 가공을 비교했다. 모두 현재 CSV와 정확히 일치하지 않았다. 가장 작은 전체평균 절대차이도0.1082, 최대 절대차이11.9026이다. 단위가 섞인 이 수치를 우열 지표로 해석하지 않는다. 이 조건들 중 가장 가까운 것을 공식 가공 규칙으로 채택하지 않는다. 원본33개 선택과 X27/X31 제외는 정황에 맞지만 정확한 창·경계·stride·1500→1499 과정은 미확정이다.

`read_original.py <ZIP 경로>`는 원본을 읽어 계산용 배열을 저장하고 `check_median_blocks.py`는 위 제한된 탐색을 재계산한다. 원본을 덮어쓰거나 기존 datasetTE.csv를 변경하지 않았다. 추가 가공 규칙을 값에 맞춰 무제한 탐색하지 않았다. 다음은 CPCaD의 실제 전처리 코드 또는 저자 측 변환 명세를 확보하는 일이며 외부 연락은 수행하지 않았다.

보완: 공개 upstream의 도달 가능한 전체11개 commit 파일명 이력에서도 .py/.m/.ipynb 전처리 코드를 찾지 못했다. 원본 세 실행 모두 XMV5=0, XMV9=0, XMV12=100이고 X27/X31 후보는 실제로 상수임을 확인했다. 다만 누가 어떤 코드로 해당 열과 첫/마지막 행을 제거했는지는 별도 미확인이다.
