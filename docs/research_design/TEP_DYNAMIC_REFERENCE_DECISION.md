### 원본 코드와 독립 계산

- `python_backend.py:179–181`: 10번 밸브 시정수5초를 `/3600`으로 h 단위 변환.
- 같은 파일 `632–638`: 초기 command와 cache를 실제 밸브 값으로 초기화, stiction 문턱2.0pp·flag0.

- 같은 파일 `1256–1259`: shutdown이면 모든 `yp`가0으로 덮어써짐. shutdown 경로를 정상식 검증에 섞지 않음.

정상 분기에서 `dv/dt=(c_t−v_t)/tau`이고 일반 Euler는 `v_next=v_t+dt*(c_t−v_t)/tau`다. 현재 dt1초/tau5초에서만 `v_next=v_t+(c_t−v_t)/5`로 줄인다. 초 값을 h 미분값에 직접 곱하지 않는다. 일반 cache식은 고착이 있어도 적용 cache를 알면 source에서 읽을 수 있지만, **이번 정상 계약은 고착/제어 개입/clip 조건을 검증하지 않았으므로 모두 거부**한다. 그 조건에서 `c=u_req`라고 대체하지 않는다.

무고착 flag0이면 t>0에서 명령 차이>0일 때 cache 갱신, 차이가0이면 이전 cache 유지다. t=0은 차이가0이어도 갱신 분기를 탄다. 고착 flag가 있을 때 시간0의 강제 갱신을 이후 모든 시간에 일반화할 수 없다. controller가 값을 갱신할 경우 `u_req≠u_eval`일 수 있다. source의 고정 메커니즘과 조건별로 활성화되는 의존성을 구분해야 한다.

## 4. B1/B2/B3 참조의 범위

### B1 내부 동적 업데이트: 조건부 기계식은 가능, 완전한 공정 GT는 아님

정상 분기·고정 dt/tau에서 `v_next=0.8*v_t+0.2*c_t`라는 **조건부 스칼라 업데이트**를 직접 정의하고 검산할 수 있다. 현재조건에서 두 계수가0이 아니므로 c와 v의 함수 의존성은 확인된다. 이것은 물리 모델 구현의 명시적 업데이트 의미이며 센서 시계열에서 발견되는 직접 간선과 자동으로 같지 않다.

이 식의 입력을 c와 v로 두면 upstream 부모는 식 밖으로 밀려난다. c를 u로 바꾸려면 이전cache·고착/문턱·clip·시각·평가명령·controller 기억/측정 입력이 필요하다. shutdown을 고정하지 않으면 전 공정 상태가 정상 분기 선택에 영향을 준다. 냉각수/에너지까지 늘리면 유입온도·액위·교반·조성·보유량·유입/유출 엔탈피·반응열·외란과 상태 보존이 추가된다. 밸브 한 개를 센서에 추가해 이들이 모두 해결됐다고 볼 수 없다.

**비간선:** 고정 c/v/dt/tau·정상 분기를 조건으로 한 스칼라 산술식에서 다른 인수가 직접 등장하지 않는다는 제한된 함수적 제외는 설명할 수 있다. 이를 전체 노드/시차 universe에서 인과관계가 없다는 음성 정답으로 승격하지 않는다. 조건 선택 자체가 다른 물리 상태의 영향을 받으며, upstream/총효과는 남을 수 있다. 유한한 미분 시험에서 반응0이라는 사실도 전 영역 비간선 증명이 아니다. 새 adjacency/GT 파일이나 F1을 만들지 않았다.

### B2 센서 중심 구조: 현재값 불충분과 과거 관측 가능성을 분리

PR18의 국소 반례는 같은41센서/12명령/외생 RNG에서 실제밸브만 달라도 냉각수 변화율이 달랐다는 것이다. 현재 센서로부터 그 숨은 상태를 하나의 값으로 복원할 수 없다는 증거다. 모든 센서의 모든 다음 분포가 식별 불가능하다는 일반 정리는 아니다.

과거 관측으로 상태를 추정할 가능성은 있지만 필요한 이력 길이, 신호 자극, 측정 잡음·조성센서 별도 지연/샘플링, 피드백 기억과 관측가능성이 입증돼야 한다. 모든 내부상태가 유한 이력으로 복원된다고 가정할 수 없다. 시차를 추가하면 참조 lag universe/관측 시각/집계/시간 주변화와 발견 알고리즘의 추정대상도 함께 정의해야 한다. 기존3분 median·lag5·정적31노드 규약을1초 source에 옮기지 않는다.

현재 전체31센서의 직접·시차·비간선 정답은 없다. 가능한 것은 조건부 내부 업데이트/일부 국소 양성 관계와 반응 기록이다. 이것을 부분 양성 그래프의 precision/F1로 채점하면 알 수 없는 관계를 거짓으로 정답화하게 된다. 기존 PC/BOSS 정적 센서 출력과 현재 내부 상태 전개식은 노드·시간·간선 의미가 다르므로 **현재는 구조 채점 불가**다.

### B3 총효과/도달: 조작 반응은 직접 간선 정답이 아님

같은 고정 simulator와 수동 정책의 기준/명령변경 실행은 가능하다. 효과의 대상은 `(초기 상태, 정책, 잡음/독립 반복, 조작 시점·크기, 관측 시각·horizon)`까지 명시해야 한다. 기존6초 paired 반응은 단일 초기점 진단이지 정밀한 평균 총효과 추정이 아니다. 이번4step 시험은 밸브 전이만 다루며 새 Y9 평균 효과를 계산하지 않았다.

XMV10→XMEAS9 반응은 밸브/냉각수/열전달/에너지 등을 거친 총반응이다. 직접 센서 간선의 정답을 주지 않는다. 무반응도 지연·상쇄·포화·잡음·정밀도 때문일 수 있어 경로 없음의 증명이 아니다. 총효과만으로 직접 구조 전체F1을 만들 수 없다. 폐루프 외부명령 덮어쓰기와 setpoint 개입은 같은 처치가 아니므로 별도 정책이다.

### A의 정확한 미확보 자료

`3_Normal Steady-State.zip`의 실제 bytes/선택 run, `SIMOUT.xlsx`·`XMV.xlsx`, timestamp/seed·disturbance 파일, model revision/controller/operating mode·초기 MAT와 실제 선택 설정, raw sampling 및3분 sliding-median 창/stride/경계/export 코드가 필요하다. 1500/1499행 차이는 UNKNOWN이다. temexd_mod.zip·tecode.zip·기술보고서는 확보했지만 benchmark와의 정확한 run 계보 및 사용 가능한 정식 MATLAB/Simulink 실행환경은 확보되지 않았다. 설치/라이선스 전역 부재를 단정하지 않으며 이번에 다시 검색·다운로드·연락하지 않았다. 기존 `TRACK_A_RECOVERY_GATE.md`의 요청안을 보존한다.

### 방법론 검토가 필요한 사항(새 외부 승인 절차 아님)

B는 동적 상태와 센서 주변화,유한 이력의 충분성,결정론적 업데이트의 관측 식별/faithfulness,조건부 regime 참조와 전체 graph 채점,제어 피드백·공통원인 처리를 검토해야 한다. C는 실행정책에 대한 총효과/초기조건 분포와 독립 반복·horizon/정밀도·조작범위 정당화가 핵심이다. A는 원저자/자료 접근자가 확인할 계보가 우선이다. 전문 지식이 필요한 쟁점을 기록했지만 교수님 검토나 외부 연락/승인을 새 필수 gate로 만들지 않았다.

## 7. 우선 권고와 다음 딱 하나의 결정

**B의 제한된 내부 동적 연구 설계안을 우선 검토할 것을 권고한다.** 이유는 밸브/상태/시간은 source에서 읽고 측정할 수 있어 기존 질문의 ‘오류 위치·방향과 실제 선택’이라는 중심을 유지할 여지가 있기 때문이다. A에는 실행할 원계보가 없고, C를 바로 선택하면 전체구조 정확도 질문을 우회하게 된다. B가 이미 타당한 전체 GT를 확보했다거나 본실험을 시작할 준비가 됐다는 뜻은 아니다.

다음 작업은 새 smoke가 아니라 **제조 연구의 관측대상을 기존31정적센서에서 명시적 내부상태·시간전개까지 확장하는 설계안을 검토할지 사용자가 선택하는 것**이다. 구체안은 `SCOPE_PROPOSAL.json`에 있다. 승인은 새 GT/모든 내부상태/발견학습/본실험 자동승인을 포함하지 않는다.

검토 입력은 이번4개 cache-step,기존3고정점 반례,REF-B 경계 부모/제어기 분석,Level3 불일치다. 승인되는 경우 다음 산출물은 **하나의 제한된 연구계약**이다: 목표 노드·시간/정책·경계,reference parent closure와 음성/미확정 universe,발견 알고리즘의 동일 추정대상,비퇴화 관측변동/식별 가정,고정 추천과 미사용 do,구조/과제 반복 단위,통과·중단 기준을 명시한다. 임의 숫자/안전 문턱을 채우지 않는다. 이 계약을 정당화하지 못하면 학습/전체F1 연구로 진행하지 않고 불가능 범위를 확정해야 한다.

밸브 추종 한 식만을 최종 과제로 삼으면 구조 지표와 선택 성능의 비교가 퇴화할 수 있다. 제한 연구계약에도 비자명한 Action–Target,오류 위치/유형의 비교 변동과 독립 실험 단위를 정당화해야 한다. 많은 시점이나 반복 rollout으로 독립 구조 수를 대체할 수 없다.

사용자가 이 범위 검토를 선택하지 않으면 원TEP는 구조평가 기록으로 유지하고 합성 오류 메커니즘 결과를 별도로 보고한다. 기술시험 하나를 더 반복한다고 Level3가 해제되지는 않는다. 원래 연구 질문·RESEARCH_DESIGN은 사용자 결정 전까지 그대로 유지한다.

source 모드는 실제 실행/commit/hash를 검사하고 기본 모드는 저장 hash·독립식·시간·분기·옛자료의 cache 누락·모의 거부를 재계산한다. CI는 후자이며 외부 source 실행이 아니다. 기존 외부 source의 Python/NumPy·sourcehash와 새 코드hash·원시SHA는 실행폴더에 기록한다. 원래 `src/verify_recovery.py` main은 과거 로그를 덮어쓰므로 이번에는 실행하지 않고 기존 점수/동결 검증기를 재사용한다. 검사 통과를 연구 가설 완료로 표시하지 않는다.

최종 로컬 전체90단위검사(신규9개 포함),7개 새/기존 검증script·39동결SHA·환경계약·상태일치 검사가 통과했다. 과거 기대값이나 원시결과를 수정해 통과시킨 검사는 없다. 신규 source 실행4step과 저장자료 검산은 위와 같이 분리했다.
