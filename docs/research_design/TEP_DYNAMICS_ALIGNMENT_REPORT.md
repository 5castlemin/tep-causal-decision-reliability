# 공식 TEP 동작 차이의 원인 대조

2026-10-30. PR #33 HEAD `51c2c76a55750fb772337f79b51f5fc8ab686ecd` 기반 후속 작업이다. 기존 3회×6시간 자료를 재분석하고, 이미 확보한 공식 모델만 실행했다. 과거 실행·판정은 덮어쓰지 않았다.

## 확인된 설정 차이

Manca `Technical_Report_V1_2.pdf`의 PDF 12쪽(인쇄 10쪽) Table 1.1은 이미지 표다. 이를 직접 읽으면 bit0/5/6/7이 1, 나머지가 0이므로 **구조 설정값은 225**다. 이전 공식 실행은 세 번째 인자를 생략하여 **0**이었다. 보고서와 실제 원본 SIMOUT의 73열도 추가 센서 활성화와 일치한다. 문헌 설정을 복원한 것이며 자료 평균에 맞춘 조정이 아니다. 출처·PDF·표 이미지 해시는 SOURCE_EVIDENCE.json에 기록했다.

`temexd_mod.c`의 첫 인자는 초기 상태 벡터, 두 번째는 C 내부 난수 초기값, 세 번째가 구조 설정이다. `[],seed`의 빈 값은 구조 플래그가 아니다. 별도로 Simulink의 Mode1xInitial 저장 상태가 공정·제어기를 초기화한다. 코드의 오래된 설명에는 52상태라고 적혀 있지만 실제 NX는 50이므로 레거시 설명을 그대로 상태 계약으로 쓰지 않는다.

225는 추가 센서, 측정 잡음/공정 외란의 난수 상태 분리, solver 독립 외란 계산 및 외란 크기 조절을 활성화한다. 측정 잡음 자체를 끄는 bit4는 0이다. `tefunc`는 출력 계산에서 추가 센서의 난수도 소비하고, `tesub7_`은 bit5에 따라 난수 상태를 선택한다. 따라서 같은 seed만 맞춘 이전 실행은 같은 난수 사용 규칙이 아니었다. 이번 대조는 네 비트를 함께 바꿨으므로 각 비트의 기여를 따로 추정하지 않는다.

원본 TOUT은 10초 간격이나 기본 `Ts_save=0.01h`는 36초다. 제어 주기 `Ts_base=0.0005h`(1.8초)와 다르다. 저장 블록의 실제 sample time을 바꾸면 solver의 출력 호출 일정도 달라질 수 있다. 가스 분석기는 0.1시간, 제품 분석기는 0.25시간 지연·갱신 규칙을 갖는다. 10초마다 저장한다고 모든 분석기가 매번 새 측정을 생성하는 것은 아니다.

## 최초 차이와 명령 기록의 위상

FIRST_DIVERGENCE.csv는 과거 3회 실행의 41센서·12명령을 원본과 대조한다. hold와 선형 보간을 구분하고 중복 시각은 마지막 기록을 사용한다. 과거 실행에서 압력·X20·X21은 첫 원본 관측인 10초부터 달랐다. 이는 잡음도 포함한 수치 차이이며 구현 오류 발생 시각이라고 해석하지 않는다. 사용한 1e-6은 위치 추적용 기준이며 센서 오차·통계 유의성·동등성 기준이 아니다.

기존 감시는 `mdlOutputs`의 **명령 cache**를 기록했다. 새 외부 명령 복사는 `getcurr(...,2)`를 부르는 미분 계산에서 일어난다. 따라서 t=0의 cache는 기본 명목값이며 원본 ToWorkspace XMV와 같은 사건이 아니다. 실제로 원본 첫 XMV12개는 이전 모델 1.8초 cache 및 새 native ToWorkspace의 초기 명령과 부동소수점 허용범위에서 일치한다. XMV5/9/12가 원본에서 0/0/100인데 초기 cache가 22.21/47.45/50이라는 사실을 제어기 불일치로 오판하면 안 된다. 명령·cache·물리적 밸브 상태를 별도로 구분했다.

## 짧은 실제 실행과 원인 분리

실행 전 EXPERIMENT_PLAN.json을 고정했다. 원본 C는 S-function 등록 이름만 바꿔 별도 MEX로 컴파일했다. 양쪽에 같은 읽기 전용 PostOutputs 감시를 붙여 원본/기존 C 감시 사본을 60초 비교했다. 470×83개 시각·41센서·40입력 기록의 최대 차이는 **0**이었다. 원본 측의 새 감시도 1.8초 주입 중단 시험에서 reason99로 중단했다. 이 비교는 내부 전체 상태의 동등성 검증이나 모든 안전 분기의 시험은 아니다. 원래 C 감시의 50상태 finite·선택 센서 범위·명령 범위·native shutdown 검사는 후속 실행에서 유지했다.

같은 초기 상태·seed1431655765·ode45 설정에서 플래그 0/225와 저장 36/10초의 2×2 조건을 각각 10분 실행했다. 225의 첫 두 시도는 모델 차원 검사에서 실패했다. 원본 파일을 고치지 않고 실행 사본의 기존 제어용 Selector 입력 너비만 73으로 늘리고, 41입력 HourlyCost 진단 앞에 첫 41개를 고르는 읽기 전용 Selector를 추가했다. 제어기 선택 인덱스·물리 방정식은 불변이다. 실패 로그와 실행 전 호환 조치 기록을 보존했다.

동일한 10초 원본 격자에서의 평균 절대 차이:

| 설정 | 압력 kPa | X20 압축기 동력 kW | X21 반응기 냉각수 출구 온도 °C |
|---|---:|---:|---:|
| 플래그0·10초 | 0.643702 | 0.232452 | 0.014577 |
| 플래그225·10초 | 0.000440 | 0.001399 | 0.000054 |

225·10초 조건에서 첫 10초의 세 값은 원본과 정확히 같았다. 0~370초의 73센서 최대 차이는 약7.43e-7, 12명령은 약4.25e-9다. 1e-6 기준의 첫 센서 차이는 380초, 첫 명령 차이는 XMV10의 390초다. 원본이 10초 기록이므로 실제 1.8초 제어 시점에서 어느 것이 먼저 바뀌었는지까지 특정할 수 없다. 10분 전체 73센서 최대 차이는0.016735, 명령은0.002658이다. 단위가 다른 변수의 절대 오차를 전역 정확도 순위로 해석하지 않는다.

36초 조건의 원본 비교는 보간 진단이다. 별도로 같은225의 36/10초 실행을 **공통 실제 시각**에서 대조하여 저장 시계 변경 자체가 trajectory를 바꾸는지 검사했다(CLOCK_DIAGNOSTIC.json). 이는 사후 보간 오차와 다른 문제다. 개별 난수 호출 스트림을 모두 계측한 것은 아니다.

10분 후에는 작은 잔차가 시간에 따라 누적되는지 확인하기 위해, 다른 설정을 바꾸지 않는 **한 번의 30분 연장**을 실행 전에 추가 고정했다. 독립 확인 실험이 아니라 동일 조건의 진단 연장이며, 별도 EXTENSION_30MIN_COMPARISON.csv와 RUN_RESULTS.json에 보존한다. 기존 6시간을 반복 생성하거나 75시간을 실행하지 않았다. 30분 연장은193.523초 wall time으로 guard0 완료했다. 30분의 최대 절대 차이는 압력1.957481kPa, X20 2.097440kW, X21 0.058588°C이며 초기의 작은 잔차가 이후 커졌다. 이 결과도 삭제하거나 마지막 구간을 제외하지 않았다.

특히 기록 격자의360초까지 명령과 세 핵심 센서가 대응하고,370초에 작은 차이가 생겨380초에1e-6을 넘었다. 공식 모델의 yA/yAC 조성 제어기는0.1시간(6분) 주기이고 가스 분석기 갱신도 이 부근에 있다. 따라서 **첫6분 조성 제어/분석기 갱신과 solver 호출순서의 상호작용**이 구체적인 잔차 원인 후보다. 원본의 내부 호출·제어기 기억 기록이 없어 원인으로 확정하지 않는다. 10초보다 짧은 원본 입력 차이를 추적했다고 주장하지 않는다.

## 남은 차이와 판정

**SAME_ENVIRONMENT_PLAUSIBLE_BUT_UNVERIFIED**: 복원한225·10초 후보에 대한 판정이다. 과거0·36초 실행은 원본과 설정이 달랐음이 확인됐다. 공정 계열 자체의 부적합이 입증된 것은 아니다. 초기화와 짧은 trajectory의 대응은 훨씬 강해졌으나, Manca 실제 MATLAB release·solver 허용오차·초기화 세부 옵션·실행 모델 bytes는 확보하지 못했다. 잔여 차이를 특정 solver 또는 제어기 기억의 탓으로 확정할 수 없다. 정확한 원본→1499행 전처리도 아직 미복원이다. CONTROL_COMPARISON.csv의17개 루프는 공식 파일의 계수·초기출력 식을 재사용해 대조한 것이며, Manca 각 루프의 실제 기억·개별 override 설정까지 검증한 표가 아니다. Table1.1에 있던 증거를 이번에 제대로 확인하여 과거의 미확인 항목을 일부 해소한 것이며, 과거 결과를 삭제하지 않는다.

따라서 원래 연구용 효과 검증 Gate는 통과시키지 않았다. 사용자가 별도 승인한 **동일환경 가정 기반 기술 개입**만 수행했다(TEP_INTERVENTION_PROBE_REPORT.md). 기존 28간선의 완전성, 관측 SCM의 식별 가능성, 구조 지표 우월성, 고장 복구·산업 안전성은 이번 결과로 입증되지 않는다.

외부 문의가 필요할 때의 초안(발송하지 않음): “공개 정상자료 재현을 위해 Table1.1의225 및10초 저장을 적용했습니다. 초기73센서와12명령이 대응하지만 이후 작은 잔차가 남습니다. 실제 생성 당시 MATLAB/Simulink 버전, solver/RelTol/AbsTol/MaxStep, 초기 상태와 제어기 기억을 포함한 모델·초기화 파일, CPCaD의 원본 선택 및 중앙값 창·이동간격·경계·첫 행 처리 코드를 제공받을 수 있을까요?”

재현: 새 격리 사본에서 `run_alignment(modeldir)` 실행. 원시 CSV/MAT·컴파일 파일은 data/local에만 보관하며, 실행 요약·해시·소스 근거·계획은 research_runs/tep_dynamics_alignment에 기록한다. 단위검사와 과거 저장 결과 재검산은 새 MATLAB 실행과 별개다.

공통 실제 시각0/180/360/540초에서225·36초 대225·10초의 최대 차이는 압력1.029975kPa, X20 0.450447kW, X21 0.019329°C였다. 이 비교는 선형 보간을 사용하지 않았다.

격리 사본 준비는 `python research_runs/tep_dynamics_alignment/prepare_workspace.py <공식 원본 디렉터리> <기존 검증 guard 디렉터리> <새 디렉터리>`로 재현한다. 입력 C 해시를 확인하고 기존 출력 디렉터리를 거부한다. 이 준비만 별도 새 로컬 경로에서 실제 확인했으며 추가 시뮬레이션은 하지 않았다. 실행 중간의 차원 호환 수정은 run_alignment.m에 명시했고, 기존 trajectory 덮어쓰기 거부는 실행 후 보강한 보호 기능이다.
