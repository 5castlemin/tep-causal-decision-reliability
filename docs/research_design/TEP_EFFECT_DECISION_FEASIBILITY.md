## 3. 후보 두 개 비교와 하나의 선택

### 후보1: 수동 XMV10 command → 미래 XMEAS9(선택한 검토 대상)

`TEPSimulator.set_mv(10,value)`는 process command를 쓰고 ManualController의 유지값도 바꾼다(`simulator.py:256–266`, `controllers.py:592–618`). 실제밸브 상태 `yy47`·적용cache·냉각수 상태·에너지/온도를 거쳐 XMEAS9에 반영된다. do(v),do(E),do(T_R)로 내부 상태를 강제하는 것과 다르다. 기준과 대안 모두 **MANUAL**로 고정해야 하며 폐루프 직접 command와 섞지 않는다.

- 초기 command41.10581288%는 source 값이며 과거 기록과 일치한다. 이는 안전 범위나 경제 최선이라는 증거가 아니다.
- fresh 객체의 짧은 exact 반복과 manual command 유지,상태/센서 시계가 기록돼 있다. 이는 장기/다중 초기조건의 평균 정책효과 검증이 아니다.
- 기존6초+.1pp의 마지막 Y9 차이 약−0.00001844°C는 국소 구현 반응이다. 기존 +1pp/600초 시작 조건은1788초 압력 한계 종료와 긴 온도변화를 보였다. 작은/큰 반응 둘 다 **선택 과제의 적절한 H나 안전 command 집합**을 자동 확정하지 않는다.
- 밸브 시정수5초·controller의3초 갱신·PI reset 시간은 공정 온도의 settling time이 아니다. 의미 있는 전체 온도 horizon은 UNKNOWN이다.
- 과거자료는 개발 증거로 위험/가능성을 검토하는 데 쓸 수 있지만,이를 새 미사용 효과 평가나 조작 허용범위 인증으로 바꾸지 않는다. 결과가 좋은 정책·시간만 사후 남기는 것은 금지한다.

### 후보2: 폐루프 반응기 온도 setpoint → XMEAS9(기각)

검토한 명령은 `sim.controller.set_setpoint(17,s)`다. source에서 이 setter는 `self.setpoints[17]` 배열만 변경한다(`controllers.py:551–560`). `_init_setpoints`는 mode1의 배열17에122.9°C를 넣지만,실제 외부 온도 루프 `ctrl18`은 별도로120.40°C로 초기화된다(196,367–370행). `calculate`는 `ctrl18.calculate_change(xmeas[8],dt3)`를 호출하며(463–465행),검토한 source 경로에 배열17을 `ctrl18.setpoint`에 복사하는 연결은 없다.

이는 **고정 source의 정적 연결 불일치**다. setter 호출 실험이나 패치를 새로 하지 않았고,라이브러리의 모든 setpoint API가 고장났다고 일반화하지 않는다. `ctrl18.setpoint`를 직접 바꾸는 별도 controller parameter 개입을 이 setter의 검증으로 대신하지 않는다. 냉각수 cascade의 배열9는 반응기 목표17과 다른 입력이며 추가 후보로 확대하지 않았다.

mode 전환도 배열 갱신/기억 reset을 포함한 여러 제어·생산 목표의 변화다. 단일 온도 목표만 바꾼 같은 정책으로 간주할 수 없다. 이 후보는 실효 명령 경로와 반복 정책 결과가 미확인이라 선택하지 않았다. 코드 수정만으로 후보1의 조작범위·목표·horizon 문제가 해결되는 것도 아니다.

현재120.4를 목표로 기본 정상점을 유지하는 과제는 항상 기준 정책을 고르는 퇴화 문제가 될 수 있다. 그러나 **기준 정책이 항상 최선이라고 증명한 것도 아니다**. source에 목표 숫자가 있다는 사실만으로 의미 있는 다른 선택지가 존재한다고 판단할 수 없다. 더 어려운 과제를 만들려고 새로운 Fault·임의 초기 상태·목표를 이번 범위에 넣지 않았다.

## 5. 선택 후보의 정책·Outcome·효과 계약

검토 정책은 t0=0부터 한 개의 constant manual XMV10 command를 유지하는 것이다. a0는 fresh source 초기화와 unchanged manual command41.10581288%,다른 명령은 원래 manual 값으로 유지한다. a1/a2는 서로 구별되고 정당한 command여야 하지만 **숫자·허용 집합은 확정하지 못했다**. 캐시와 밸브 동역학을 생략하지 않고,controller/mode/초기 기억을 같게 둬야 한다.

초기 P0는 후보 수준에서 재현 가능한 **단일 source 초기상태 x0의 점질량**으로 제한할 수 있다. 이는 여러 운전점에 대한 평균 효과가 아니다. seed/외생 잡음 모집단은 별도로 사전 고정해야 하며 현재 실제 평가용 분포·seed 명세는 없다. 같은 seed의 반복 경로는 독립 표본이 아니다.

Y는 **evaluate 시각 H의 XMEAS9**,단위°C다. 적분 후 state_H와 직전 측정cache를 같은 시각이라고 쓰지 않는다. 내부 T_R는 센서잡음을 제외한 별도 진단이고 primary 결과와 섞지 않는다. H는 미확정이다.

```text
단일경로 반응: Y^a(H;x0,epsilon) - Y^a0(H;x0,epsilon')
고정 x0의 평균 정책효과: E_epsilon[Y^a(H)|x0,MANUAL] - E_epsilon[Y^a0(H)|x0,MANUAL]
운전조건 평균 효과: E_P0,epsilon[Y^a(H)] - E_P0,epsilon[Y^a0(H)]   # 별도 P0 필요
```

서로 다른 epsilon이면 첫 식은 paired 반사실 차이가 아니라 두 실행의 차이다. 관측회귀 예측값과 실제 simulator 정책 결과도 구분한다. 미래 평균 결과가 제대로 정의될 때만 ATE 표기를 사용할 수 있다. 그 기준은 **이 구현/정책/초기조건/잡음**에 대한 계산 기준이며 실물 플랜트나 CPCaD 원환경의 효과 정답이 아니다.

### 실패·종료

shutdown/step false/비유한값·마지막 상태/센서 시계·H도달 여부를 보존한다. H에 못 도달했다면 Y(H)는 미정이며 마지막 값을 그대로 H의 결과로 대입하지 않는다. 도달한 실행만 평균하면 선택된 조건부 결과이지 원래 무조건 평균이 아니다. 실패를 포함하는 loss/효과의 최종 정의가 없으므로 현재는 ATE나 단일 최적화 손실을 계산할 수 없다. source가 종료 뒤 값을 반환할 수 있다는 것과 그 값이 유효한 H 결과라는 것은 다르다.

## 6. 손실과 비자명성 판정

검토할 tracking risk는 다음이다.

```text
R(a) = E[(Y^a(H)-y_target)^2]
     = (E[Y^a(H)]-y_target)^2 + Var(Y^a(H))
경제/조작비용을 정당화한 경우에만 L(a)=R(a)+lambda*C(a)
평균반응 진단 M(a)=(E[Y^a(H)]-y_target)^2 는 R(a)와 별개
```

목표·비용 함수·lambda를 source 숫자로 임의 채우지 않았다. 가격/운전비 자료가 없다면 비용 항을 제외한 **unpriced tracking 비교**를 별도 제한 실험으로 설계할 수는 있지만,이를 조작비용0인 실제 경제 최적화라고 부를 수 없다. 비용 부재만으로 STOP을 내린 것은 아니다. 허용 정책 집합/H/선택 변동과 실패 포함 손실이 함께 미정이다.

평균만 예측하는 모델로 R을 최적화하려면 별도로 분산/2차 모멘트를 다뤄야 한다. 등분산이나 센서잡음의 정책별 상쇄를 자동 가정하지 않는다. 평균 예측 오차가 작아도 후보별 순서가 잘못되면 선택 손실이 클 수 있고,큰 예측 오차가 있어도 같은 정책을 골라 손실 차이가 없을 수 있다. 효과 방향 정확도·효과 크기 오차·선택 손실을 각각 측정해야 한다.

| 핵심 조건 | 현재 판정 |
|---|---|
| 정책에 따른 온도 변화의 경로 | 코드/과거 반응으로 지원됨. 독립 평균 효과 정밀도는 미확인 |
| 최소 두 개 의미 있는 정책 | API 숫자를 다르게 쓰는 것은 가능. 물리·과제상 의미 있는 비교 집합은 UNKNOWN |
| 고정 목표/H/비용의 정당화 | source의 nominal 숫자는 있으나 일관된 비자명한 선택 과제는 미정 |
| 기준 유지만 항상 선택되는가 | UNKNOWN. 기준최선/비최선 어느 쪽도 주장하지 않음 |
| 예측 오차→잘못된 선택의 실제 변동 | 연구할 가능성은 있으나 현재 자료로 확정 안 됨 |
| 종료를 포함한 완결된 목적함수 | 미정. 임의 penalty·생존자만 평가·마지막값 보간은 채택 안 함 |

## 7. 모델 역할: 이름을 늘리지 않음

후속 과제가 정당화된다는 가정하에 역할 두 개만 검토했다. 현재 eligible model은0개이며 학습하지 않았다.

1. **유한 정책별 반응 통계 기준선:** 동일 source·정당한 정책 할당·과제의 train/calibration 결과만으로 평균/2차 모멘트를 예측한다. 최종 F 결과를 미리 읽는 “기준선”은 금지한다.
2. **선형 action+사전 history 예측기:** 결정 시점까지의 XMEAS/XMV와 후보 command만 사용하고 train-only 전처리를 적용한다. action variation/overlap·식별 자료가 없으므로 관측회귀에 인과효과라는 이름을 붙이지 않는다. primary는 sensor-only이며 내부 미래밸브/E/참조 trace를 제공하지 않는다.

nonlinear/time-series family와 SCM은 과제/자료/식별이 없는 상태에서 확대하지 않는다. 기존 Ridge 정적 평균 전개/합성 추천기는 **평균반응 제곱손실** 중심이므로 새 기대 tracking risk에 그대로 붙이지 않는다. 기존 F1·계수·임계값을 이식하지 않는다. privileged-state 실험을 나중에 한다면 simulator-only 별도 실험으로 구분해야 하며 현재 포함하지 않는다.

## 8. 독립 평가와 참조 최적 정책(형식 설계만 완료)

훈련 D,모형선택 V,진단 참조선택 R,최종평가 F를 **완전 trajectory/초기조건·seed namespace**로 분리한다. 정책 A·목표/H·loss·실패/P0·잡음·후보선택 규칙은 결과 전에 고정해야 한다. 모델/추천을 저장·hash 고정한 뒤 simulator 결과를 읽는다. 과거 PR18/19 진단은 개발 근거이며 미사용 final이 아니다.

R에서 정한 최선은 **사전 유한 후보 중 empirical reference**다. 그 정책과 모델 선택을 고정한 뒤 별도 F에서 비교한다. 이 차이는 고정 참조와의 손실 차이이며 음수가 나올 수 있다. 진짜 최적 a*에 대한 항상 비음수인 regret라고 포장하지 않는다. F 자체를 다시 최소화하면 in-panel empirical minimum과 선택 편향이 포함되므로 독립 oracle로 부르지 않는다. global continuous optimum도 아니다.

동일 정책·context의 평가 결과는 모델 간 공유할 수 있지만 의존성을 보존해야 한다. 기본은 arm별 독립 평균,CRN은 실제 외생경로/호출 불변성이 검증될 때만 사용한다.6초의 RNG 일치는 임의 H/Fault/정책에 대한 보장이 아니다. 표본 수·정밀도·seed 집합을 사후 유리하게 늘리지 않는다.

효과 예측은 고정 Action의 outcome/효과 크기·부호와 정상 관측 MSE를 분리한다. 선택 성능은 실제 선택·a0 대비 개선/악화·공통 후보에서의 손실·참조선택 오차·가용률·shutdown을 함께 보고한다. fit/recommendation 실패 시 사전 a0를 실행하는 운영 정책과 가용 모델의 조건부 성능을 구분한다. simulator failure를 모형 실패의 fallback이나 임의 큰손실/0으로 숨기지 않는다. 같은 graph/모델의 rollout·행·정책 반복은 독립 graph-quality 표본이 아니다.

이 설계 절차가 있다는 사실만으로 task·data·loss가 채워지지는 않는다. 독립 평가의 데이터 생산/정책 최적화는 실행하지 않았다.

## 9. 최종 판정과 중단의 의미

**STOP-TEP-EFFECT-TRACK**을 선택한다. EFFECT-DESIGN-READY가 아니고,최대 두 개의 작은 구현 확인만 남은 CONDITIONAL-DESIGN도 아니다. 후보1에 명령 API는 있지만 핵심 과제 정의/operating admissibility/H·선택 변동/실패 손실/학습자료의 정책 범위가 함께 미정이며,후보2는 setpoint 경로조차 지원되지 않는다. setter를 고치거나 짧은 smoke를 반복해도 이 규범적·과학적 결핍이 해결되지 않는다.

이는 모든 TEP 구현에서 효과 연구가 불가능하다는 정리가 아니다. **현재 확보 근거와 이번 두 후보에 대한 연구 착수 불가 판정**이다. GT 없이 효과 평가가 가능하다는 일반 원리를 부정하지 않는다. 다만 가능한 API를 의미 있는 제조 선택 과제로 포장하지 않는다. 현재 경로는 동결하고,추가 TEP 시험·패치·운전범위 찾기·후속 검토문서 생성을 다음 작업으로 제안하지 않는다.

원래 CPCaD와 합성 연구는 보존한다. 논문/최종 보고서에서 합성 결과는 구조오류–효과예측–선택 손실의 별도 근거이고,Python 기록은 국소 구현/수치·초기화/환경 한계 근거다. Python에서 성공한 구조–선택/효과–선택 실험이 존재한다고 쓰지 않는다. 관측 MSE나 짧은 반응을 제조 효과성·복구·안전 성공으로 바꾸지 않는다.
