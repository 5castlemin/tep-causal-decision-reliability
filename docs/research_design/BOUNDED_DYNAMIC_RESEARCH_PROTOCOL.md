`c=vcv[9]`는 적용 cache 진단으로 별도 기록한다. 정상 수동에서 c=u인 열을 둘 다 학습하면 결정론적 중복이 생기므로 노드에서 제외하되 cache 일치 가정을 검사 없이 생략하지 않는다. 열전달 Q와 반응기 T_R는 대수 중간/읽기값으로 둔다. T_R와 E를 독립 상태인 것처럼 이중 채점하지 않는다. T_R는 최종 물리 목표,센서 Y9는 추가 센서잡음·평가시계가 있는 보조 readout이다. 자동 PI 기억은 이번 mode 밖이므로 자동 제어를 섞으면 계약 불일치다.

이 선택은 편의를 위한 전체 GT 축소가 아니다. 중간 대수량을 치환한 **축약 수치 전이의 직접 부모**를 비교하겠다는 제안이며,원래 물리 그래프의 elementary edge나 센서 직접 간선과 다른 추정대상이다.

## 3. 방정식·부모 폐쇄성과 경계 실패

모델 시간 h,dt=1/3600 h. 원 source `python_backend.py:811–867,1008,1116–1125,1224–1259`와 `simulator.py:308–334`를 기준으로 한다. [고정 backend](https://github.com/jkitchin/tennessee-eastman-profbraatz/blob/9a6c8e5fcef4a2850778704e7793c87b0a187005/src/tep/python_backend.py), [고정 simulator](https://github.com/jkitchin/tennessee-eastman-profbraatz/blob/9a6c8e5fcef4a2850778704e7793c87b0a187005/src/tep/simulator.py).

```text
v_next = v + dt*(c-v)/tau                 tau=5/3600 h
fwr = 10*v
Q = UA*(W-T_R)*D
W_next = W + dt*[500.53*fwr*(T_in-W)-Q*10^6/1.8]/7060
E_next = E + dt*[hst6*ftm6-hst7*ftm7+reaction_heat+Q]
T_R = inverse_liquid_enthalpy(E/U_liquid, composition)
```

| 종속변수 | 닫힘 판정 | 빠진 실제 부모/체제 | 외부 고정/조건화가 해결하는가? |
|---|---|---|---|
| v_next | 좁은 정상 분기에만 조건부 닫힘 | 이전cache·고착·clip·tau·dt·shutdown·평가명령/제어정책 | 기존4step은 검증. 전체 공정/다른체제까지 닫힌 것은 아님 |
| W_next | **NOT_CLOSED** | T_in의 walk/외란,UA의 액체체적·실제 교반상태,D,T_R의 E/성분/holdup,shutdown | 읽을 수는 있지만 대부분 직접 제어 불가. 상태·체적/조성은 u에 반응하는 공정의 일부 |

| 최종 T_R(H) | **NOT_CLOSED** | 미래 액체 holdup·조성·역산의 수치 조건 | E(H) 하나로 온도를 정할 수 없음. action 뒤 미래 조성 제공은 예측에 unavailable한 정보일 수 있음 |

`UA`는 액위/체적과 교반 밸브 상태의 함수다. `hst6*ftm6-hst7*ftm7+reaction_heat`도 주변 공정과 원자로 상태의 내생적 집계다. **진단값을 읽을 수 있다는 사실은 외생성·직접 제어가능성·조작 간 불변성을 뜻하지 않는다.** 같은 시점의 경계값을 관측회귀에 조건화하는 것과 여러 step의 개입 효과를 예측하는 것도 다르다. 미래 경계값의 생성식은 후보 모델에 없다.

기준 실행의 미래 경계 trace를 조작 실행에도 고정하면 조작에 따라 되돌아오는 공정 경로를 막은 다른 모델이 된다. 그것은 단순 데이터 전처리가 아닌 추가 개입/모형 변경이다. 실제 조작 후 경계 trace를 추천기에 주면 평가 정보 유출이 된다. 어느 쪽도 승인하거나 프로토콜의 해결책으로 채택하지 않는다.

부모 폐쇄를 위해 전체50state/제어기를 모두 추가하거나,남은 차이를 독립 잡음으로 정의하는 조치는 이번 범위를 벗어난다. 별도의 축약모델 타당화·경계 제어 또는 잠재변수 주변화 정의가 필요하다. 단순 source 호출관계 추출이나 새 schema로 해결되지 않는다.

정상 체제의 의미도 기록해야 한다. manual/IDV0/비포화/비고착/source 운전점·초기화·dt 고정을 요구하지만,조작 후 shutdown 여부로 살아남은 실행만 선택하면 post-treatment selection이 된다. 허용 조작/운전분포 내 체제 유지 근거 또는 실패를 포함한 별도 효과 정의가 필요하다. 현±0.001pp/6초 기술 시험을 일반 안전·학습 범위로 승격하지 않는다.

## 4. 유한 채점 대상: 정의는 가능, 정답화는 아직 불가

제안한 후보 universe는 `U1=V(k)×{v,W,E}(k+1)`의12쌍이다. 자기 전이 v→v,W→W,E→E도 포함한다. 이는 dt1초 Euler의 한 step 표현이며 연속시간 미분의 직접성/정적 DAG/3분 median 관계와 다르다. 같은 시점 관계 U0는 별도로 제외하고,sensor/readout·정책 u_next 식·역시간 방향도 이 universe에 섞지 않는다. lag>1은 **참조 없음/범위 제외**이지 간선 없음이 아니다.

다음 표는 source 기반 **조건부 함수 검토**이며 GT 라벨이 아니다. 모든12쌍의 discovery 채점상태는 NOT_ADJUDICATED다.

| 도착 | 출발 u | 출발 v | 출발 W | 출발 E |
|---|---|---|---|---|
| v_next | 조건부 의존 지원 | 조건부 자기 의존 지원 | 좁은 식에서 제외 | 좁은 식에서 제외 |
| W_next | 같은 Euler step의 좁은 식에서 제외 | 조건부 의존 지원 | 조건부 자기 의존 지원 | T_R/UA를 치환한 의존 후보·경계 미폐쇄 |
| E_next | 같은 step의 좁은 식에서 제외 | 같은 step의 좁은 식에서 제외 | 조건부 열전달 의존 지원 | 자기 보존/온도·반응·흐름 치환 후보·경계 미폐쇄 |

5개의 식 안 제외를 정당한 전역 음성쌍으로 바꾸지 않는다. 예를 들어 u는 이1step W 식에 없더라도 다음 v를 거쳐 이후 W에 영향을 준다. shutdown 선택/미포함 경계/축약과 통계적 주변화도 분리해야 한다. u→v의 근거 역시 c=u라는 조건 밖에서는 그대로 쓰지 않는다. 신호가0인 한 점이나 희소성을 비간선 근거로 사용하지 않는다.

현재 discovery용 정당화된 음성쌍 목록은 비어 있다. 참조 구조 파일/adjacency/새 F1을 만들지 않았다. 전체·방향 F1/SHD는 **고정 노드·시간 U,정당화된 양성/음성/미확정 분할,동일한 발견 추정대상,과제 정의**가 모두 통과한 뒤에만 후속 설계에서 허용할 수 있다. 부분 참조는 별도 coverage/기권·불확실 규약을 먼저 고정해야 하며,현재 채점 승인된 부분집합도 없다. 양성만 평가한 recall을 F1이라고 부를 수 없다. 여러 경로의 union recall은 허위 경로를 벌하지 않으므로 정확한 참조가 생겨도 방향 F1/오류 위치·추가 경로를 함께 다뤄야 한다.

## 5. 발견 대상과 관측 설계

내부상태는 simulator에만 있는 privileged 정보다. 같은 값을 실제 제조센서에서도 안다고 일반화할 수 없다. 기존 manual 기준 자료의 명령 변동폭0과 정상 고정점은 식별에 충분한 자극 증거가 아니다. 독립/충분한 정책 변동을 설계할 합리적 여지는 있지만,허용 물리 범위·정상성·효과크기·유효표본수·독립 혁신잡음이 아직 없다. 행 수를 늘리거나 인공 잡음을 넣어 알고리즘 가정을 맞추는 방식은 채택하지 않는다.

| 유형 | 실제 추정대상과 현재 후보의 불일치 | 후속 허용 조건 |
|---|---|---|
| PC-stable/BOSS 등 정적 방법 | 정적 변수의 구조/동치류를 추정. 순수 시계열 행을 독립표본으로 취급하거나 임의 lag stacking을 해도 자동으로 한step의 함수 부모가 되지 않음 | 적절한 독립 실험 단위/시간전개·경계·동치류 규약을 정당화하기 전 제외 |
| 충분한 관측을 전제하는 PCMCI+형 | lag/동시점 time-series 관계를 대상으로 한다. 이4node의 숨은 경계·유효 Markov 차수·결정론적 의존/faithfulness·자극은 미확정 | 부모 폐쇄와 시간/잡음·정상성·검정 가정이 성립할 때 후보 검토;현재 미선정 |
| 잠재변수 time-series 방법(LPCMCI형) | 숨은변수를 허용하지만 목표는 ancestral/PAG 주변 표현. 내부 업데이트의 직접 부모와 같지 않으며 lag 창도 참조 의미에 관여 | 해당 주변 참조/시간창/selection 가정부터 정해야 함. PAG endpoint를 강제로 DAG 방향으로 바꾸어 채점 금지 |
| 선형 비정규/선형 동적 모형 | 비선형 열역학·결정론적 상태식·생략 경계가 선형/독립 혁신 가정에 맞는지 미확정 | 기존 Direct/VAR 계열을 이름만으로 같은 정확도 비교에 넣지 않음 |

알고리즘 자료는 실제 학습 없이 공식 문서/원논문만 확인했다. [PC](https://causal-learn.readthedocs.io/en/latest/search_methods_index/Constraint-based%20causal%20discovery%20methods/PC.html), [BOSS](https://causal-learn.readthedocs.io/en/latest/search_methods_index/Permutation-based%20causal%20discovery%20methods/BOSS.html), [PCMCI+ 원논문](https://proceedings.mlr.press/v124/runge20a.html), [LPCMCI 원논문 §2](https://arxiv.org/html/2007.01884v3#S2). 이는 TEP에서 가정이 통과했다는 증거가 아니다. PCMCI+는 causally sufficient case를 다루고,LPCMCI는 latent projection/시간창·정상성·faithfulness 등을 전제로 한다. 기본 설정/성능/논문의 보장을 이 simulator에 이식하지 않는다.

따라서 현재 승인된 학습 알고리즘은0개다. 버전/검정·score/lag/threshold는 observation-only 개발 자료에서 사전 고정해야 하며 GT/F1/독립 효과 결과로 튜닝하지 않는다. linear Ridge 또는 비선형 회귀를 잘 적합해도 빠진 경계와 식별 문제가 사라지지 않는다.

## 6. 비자명한 조작 선택 과제: 별도 핵심 gate 실패

실무 Action은 **외부 수동 XMV10 명령 정책**이다. do(v),do(E),do(T_R),cache 직접 대입은 source에 접근할 수 있어도 물리 조작과 같지 않으므로 후보 Action이 아니다. 다른 수동 명령은 기존 policy로 유지하고 자동 setpoint/override와 섞지 않는다.

후보 과제는 unchanged u0 정책과 구별되는 admissible a 정책에서 미래 T_R(H)의 평균을 목표에 가깝게 하는 것이다. u0의 초기 source 값은 알려져 있지만 최선 정책·정상 물리 기준으로 검증된 값은 아니다. **a 값/물리 허용범위/목표 온도/H/비용은 모두 미확정(null)**이다. API0..100은 안전·운전 가능 범위가 아니다. 이전+.1pp/.001pp는 기술 증거이지 이 숫자를 그대로 탐색/추천 범위로 정할 근거가 아니다.

최소 두 개의 구별되는 선택이 필요하지만 둘이 의미 있는 손실 차이를 갖거나 오류에 따라 선택이 바뀐다는 근거는 없다. 미래 온도에는 빠진 holdup/조성과 에너지 흐름이 필요하다. 단순히 밸브 v_next를 u와 맞추는 과제로 바꾸면 지연된 여러 경로/오류 위치의 차이가 사라져 원래 연구가 퇴화할 수 있다. 이것을 이번 프로토콜의 중단 조건으로 둔다.

예상되는 위치별 오류의 역할은 검토 가설일 뿐이다. u→v 누락은 구동효과를 줄이고,v/W 관련 오류는 전달을 왜곡하며,W/E와 열/반응 경계 오류는 온도 크기·방향을 바꿀 수 있다. 하지만 현재는 같은 유효한 참조/SCM/정책에서 이 차이를 분리할 수 없다. 경로부재→기준조작이라는 추천규칙도 별도로 구분해야 한다. 좋은 F1이나 큰 효과를 보고 목표/비용/과제를 골라 남기는 행위는 금지한다.

손실 제안은 `(평균 T_R^a(H)−목표)^2+조작비용`이다. 개별 sample 제곱오차 평균과 다르다. 기준 대비 개선/악화,후보 중 최선 대비 추가손실,고정조작 효과 방향·크기오차,선택불일치와가용률을 분리한다. 현재 수치는 산출하지 않는다. 물리 Recovery/Safety 과제는 이 계약에 없다.

## 7. 독립 평가·분석 계약(향후 조건부,이번 실행0)

1. source/model/controller/초기화·regime·시간계약을 같은 namespace로 고정한다. 분포 P0는 실제로 fresh 객체에서 재현 가능한 운전조건/외생 이력을 정의해야 하며 현재 미정이다.
2. 완전 trajectory와 초기조건/seed namespace 단위로 train/selection/final evaluation을 나눈다. PR18/19의 이미 본 진단기록은 개발 근거이며 untouched holdout이 아니다. 임의 행분할은 하지 않는다.
3. 같은 입력·전처리·함수 family/선택 규칙·Action·비용·시간으로 graph별 수치 모델을 적합한다. 구조/계수/함수 오류를 섞지 않도록 고정 Action 예측을 최적 선택과 먼저 분리한다. 참조가 타당해질 때만 동일 family의 oracle를 진단으로 추가하며,실제 발견 결과와 합치지 않는다.
4. graph/모델/추천을 저장하고 hash로 고정한 뒤 미사용 환경 조건에서 독립 simulator 결과를 평가한다. 평가의 미래 경계나 최적 조작을 추천기에 제공하지 않는다.
5. estimand는 명시된 P0와 manual 정책에서 `E[T_R^a(H)]−E[T_R^reference(H)]`다. 기본은 arm별 독립 표본 평균이다. common random numbers는 외생경로/호출 순서 불변성을 별도로 입증했을 때만 사용하고 동일 seed만으로 paired 반사실을 만들지 않는다.
6. state_k/센서 evaluate_k/cache를 분리한다. T_R(H)는 해당 state에 대한 **실제 evaluate 시각**의 내부 readout으로 정의해야 한다. 적분 후 state_H와 직전 센서cache를 섞거나 로깅 때문에 추가 noisy evaluate를 호출하는 설계는 안 된다.
7. discovery 실패/SCM 적합 실패/경로부재 대체/정책 실패/시뮬레이터 실패를 분리한다. 모델 실패 시 사전 기준조작을 실제 실행하는 운영 정책과 조건부 가용 모델 성능을 나눠 보고한다. shutdown은 효과의 실패/결과로 보존하며 조용히 삭제하거나 임의 거대손실/0을 대입하지 않는다. 실패 포함 estimand/loss가 미정이면 실행 중단이다.
8. 동일 source의 graph-training trajectory 묶음/운전조건/과제에 계층 의존성이 있다. 알고리즘 출력·정책·시점·같은seed replay·rollout은 독립 구조 표본이 아니다. 구조 지표의 변동과 독립 비교 정밀도가 없으면 설명력 순위를 내지 않는다. 표본 수/임계값/검정력 수치를 새로 만들지 않았다.

## 8. 판정과 범위 결정

**판정2를 선택한다.** 네 노드·12후보쌍을 적을 수는 있지만,다음 필수조건을 만족하지 못한다.

| 조건 | 현재 결론 |
|---|---|
| 부모/경계 | W/E/T_R의 내생 부모 미폐쇄. 읽기·조건화·baseline replay로 자율 개입모델이 되지 않음 |
| 참조/발견 일치 | 조건부 업데이트와 관측/latent projection의 추정대상 불일치. discovery용 음성쌍0,채점 허용0 |
| 자극/식별 | 정상기술자료의 상수 입력·결정론적 중복과숨은기억. 적절한 학습분포/유효잡음/유효차수 없음 |
| 의사결정 | 실행 가능한 command API는 있으나 의미 있는 후보/온도목표·horizon/비용/실패계약 미정. 밸브 추종으로 축소 금지 |
| 독립평가 | 절차의 초안은 있으나 위 조건/P0/과제/정밀도 미확정이므로 ready 아님 |

첫 번째 문제는 source 정적 검산·추가 valve smoke·schema 작성만으로 해결되지 않는다. 작은 축약모델이 조작 아래 자율적으로 유효한지 정당화하거나,명시적 latent projection/경계 제어로 연구 대상을 바꾸는 방법론적 근거가 필요하다. 실제 정식 운전/허용 조작 자료도 과제 설계에 필요하다. 쟁점 검토를 위해 외부 전문 지식이 유용할 수 있지만 새 교수님/외부 승인 절차를 만들거나 연락하지 않았다.

### 후속 방향 권고

- **A 원환경 복원:** 원래 질문에 가장 가까우나 정확한 run/raw·controller·집계·정식 MATLAB/Simulink가 미확보. 새 단서 없는 반복 탐색은 하지 않는다.
- **B 내부 동적 구조 연구:** 이번 계약으로는 본실험 확장을 **중단**한다. 이전 PR19의 B 검토 권고를 실제 검토한 결과이며,권고를 유지하려고 실패 조건을 완화하지 않는다. 더 많은 state/조건·독립잡음을 임의 추가하지 않는다.
- **C 별도 효과·조작 선택 중심 연구:** Python 전체 simulator가 내생 경계를 자연스럽게 진화시키며 정책 결과를 측정하므로,닫힌 작은 직접GT를 요구하는 B보다 상대적으로 현실적이다. 다만 허용 Action·P0·H·실패·정밀도 계약이 필요하고 아직 실행 준비는 아니다. **전체구조 F1의 제조 설명력 검증을 보류/수정하는 별도 질문**이므로 자동 채택하지 않는다. 여기서 얻을 정책 응답도 해당 Python 구현의 계산 결과이며,실물 공정이나 CPCaD 원환경의 효과 정답이 아니다. 장기 수치 신뢰성/운전 범위는 기존 PARTIAL 상태에서 별도로 남는다.

**다음 딱 하나는 C의 별도 효과·조작 선택 중심 설계 검토로 범위를 바꿀지 사용자가 결정하는 것**이다. 입력은 이 계약의 부모폐쇄 표/12후보쌍의 미채점 상태/선택 과제 실패와 기존 실제 API·초기화·시계 근거다. 결정은 설계 검토만 대상으로 하며 GT·데이터 생산·do 실행을 승인하지 않는다. 선택된다면 완료 기준은 ‘전체F1 주장을 제외한다’는 해석 한계와 독립 정책효과 estimand·출처가 있는 과제/실패처리를 명시한 하나의 평가계약이다. 선택되지 않으면 제조 직접 검증을 중단 상태로 유지한다.

원래 CPCaD 연구는 frozen 구조 평가·관측 적합 기록으로,합성 연구는 구조오류–의사결정 메커니즘 증거로 각각 보존한다. 둘을 Python 정책효과의 정답으로 합치지 않는다. 원래 가설은 연구 질문으로 유지되지만 **현재 Python 축약계약으로 답할 수 없다는 것이 이번 검토의 결론**이다.
