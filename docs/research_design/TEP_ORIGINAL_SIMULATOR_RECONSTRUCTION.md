# TEP 원본 생성환경 복원 가능성

2026-10-29. **TEP_RECONSTRUCTION_PROMISING:** 공식 2015년 모델과 바이트가 일치하는 공정 코드·초기 상태를 사용하는 Python 후보가 확인됐다. 기존 관측 데이터의 정확한 생성환경과 독립 개입·참조 구조의 일치는 아직 입증되지 않아 연구환경 사용은 차단 상태다. 공정 이름이나 정상 평균의 근접성만으로 동등성을 인정하지 않는다.

## 원본 계보와 확인 수준

[CIPCaD 논문](https://arxiv.org/abs/2208.01529)은 Manca 정상 자료의 원측정 0.1Hz, 75시간, 3분 이동 중앙값과 1500개 표본을 보고한다. Manca 기술보고서는 2015년 수정 Simulink 모델, Ricker 제어와 별도 시간 기록을 보고하며 MV5·MV9 폐쇄와 MV12=100인 운전점을 설명한다. 이는 **문헌 보고**이며 현재 1499행의 특정 원시 파일·seed·정확한 중앙값 stride/경계·첫 행 삭제와 연결한 재현은 아니다. 현 데이터는 33개 중 X27/MV5와 X31/MV9가 없고 논문은 분산 0 제거를 보고하지만, 원래33열의 분산과 실제 제거 코드는 미회수여서 이유의 연결은 추정이다.

Ricker 보관본 `temexd_mod.zip` SHA-256 `e43227aaded739cfeba1ec281c54ac8a549f60753e064305a669b906c4b16b0d`의 `MultiLoop_mode1.mdl`은 ode45, 상대 허용오차 1e-6, 초기 상태 로딩을 선언한다. archive Mode1 제어 설정의 압력/액위/온도는 각각 2800kPa/65%/122.9°C다. 실제 Manca가 사용한 모델 바이너리·컨트롤러 판본·초기화·잡음·외란·난수 seed·자동 보호/제한 설정은 확인되지 않았다. 초기화 파일의 존재와 실행 당시 그 파일을 사용했다는 증거도 구분한다. [공식 2015 보관소](https://depts.washington.edu/control/LARRY/TE/download.html), `TRACK_A_RECOVERY_GATE.md`, `BENCHMARK_COMPATIBILITY_DECISION.md`.

## 후보 A와 B: 공식 모델 및 TEP Studio

이번 PATH에서 MATLAB·Simulink 명령을 찾지 못했고 다른 설치 위치 전체나 라이선스의 부재를 증명하지 않았다. 기존 registry·일반 설치 경로 조사도 미발견이다. `.mdl` 로드/MEX/75시간 생성은 **NOT_RUN**이다. IEEE 정상 ZIP은 목록이 확인됐으나 접근에는 로그인이 필요한 것으로 기존 감사에서 확인했고 raw run·timestamp·seed·export 코드가 없다.

TEP Studio `852f0c69ab974540750d61bd1dbfafd56bfd80bb`의 `temexd_mod.c`, `teprob_mod.h`, `Mode1xInitial.mat` 바이트를 기존 공식 ZIP과 이번에 직접 대조했다. 각각 SHA-256은 `eff57b75700e7472005785150c21f82b0c3d178ebceebe37e532794f23785aba`, `fa3782a07c11e5c149ad0f44ec332c45ed998edb7ef8241fade9b1d395577363`, `40eaebc92badb04ad026e358cfd28ec9c778fcf2d24a1b8f5d85565854da2747`로 일치한다. 세 파일의 일치는 전체 시뮬레이터·원본 데이터 동일성의 증명은 아니다.

Studio는 해당 C 코드의 CFFI 빌드와 Python으로 옮긴 Ricker 제어기를 사용한다. source의 기본 `enable_overrides=False`, `%G` feedback 기본 비활성은 명시적 설정이며 예제에는 override=True가 있어 혼동하지 않는다. Ricker 원본과 제어 실행 순서·시계·초기 controller memory 및 noise가 동일하다는 검증은 없다. 기존 설치 기록은 Microsoft C++ 14 이상 필요로 실패했고, 이번 PATH에서도 C compiler가 확인되지 않았다. PyPI 0.2.0 공식 파일 목록은 source tarball만 제공했다. Studio 설치/새 실행은 **NOT_RUN**, 과거 빌드 실패는 보존한다. BSD 라이선스 선언과 원본 Ricker 파일 재배포 권리는 따로 확인해야 한다. [Studio 소스](https://github.com/khalidlabs/tep-studio/tree/852f0c69ab974540750d61bd1dbfafd56bfd80bb).

## 후보 C: 실제 10분 설정 진단

고정 Python TEP `9a6c8e5fcef4a2850778704e7793c87b0a187005`의 simulator/backend/controller/constants 네 파일 해시를 검증하고, 실행 전 `PLAN.json`에 seed 465120799, 1초 Euler, 정상 폐루프, 600초 두 조건을 고정했다. 기존 설정(액위75%, 온도120.4°C)과 보고된 Mode1 액위65%, 온도122.9°C를 `ctrl17`, `ctrl18`에 적용한 조건을 각각 fresh 객체에서 실행했다. 압력 2800kPa에 대응하는 동일한 setpoint 인터페이스는 확인되지 않아 설정하지 않았다. 두 조건 모두 600초 완료, 종료·비유한값은 없었다. 다른 setpoint·초기 상태·제어 정책은 결과에 맞춰 조정하지 않았다.

온도는 이동했지만 압력·액위는 10분에 목표와 일치하지 않고 X32도 크게 움직였다. 이는 **과도 응답**이며 새 정상상태나 75시간 결과가 아니다. 설정 차이가 영향이 없다는 증명도, 설정 차이만이 원인이라는 증명도 아니다. 데이터의 3분 중앙값과 1초 원시 출력은 시간·집계가 다르다. 같은 seed가 행별 동일 잡음을 보장하지 않는다.

## 개입과 28개 참조 간선

이번 진단은 setpoint 변경이며 밸브 수동 조작이나 복구 실험이 아니다. 이전 고정 Python 후보의 6초 기록에서는 수동 XMV10 명령을 유지했으나 폐루프에서는 제어기가 외부 명령을 덮어썼고, 밸브 물리 상태·센서 기록 시계도 명령과 구분됐다. 이는 국소 실행 증거이며 새로운 독립 평균 효과·고장 복구·안전 지표는 **NOT_RUN**이다. 기존 두 환경의 차이가 남아 기존 7개 그래프 F1과 결합하지 않는다.

28개 간선은 기존 benchmark의 구조 평가 참조로 보존한다. 물리 상태 업데이트의 일부 국소 관계는 검산됐지만 숨은 밸브 상태·제어기 기억·시간 지연을 센서 직접 간선으로 바꿀 수 없다. 전체 31변수의 정당화된 양성·비간선과 미확정 관계 분할은 아직 없다. 따라서 전체 참조 정확도와 실제 개입 손실을 한 환경에서 검증하지 못했다. 기존 GT를 수정하거나 임의의 전체 정답을 생성하지 않았다.

## 재현과 다음 조건

`python -X utf8 scripts/run_tep_setpoint_reconstruction_probe.py --source <고정 Python TEP 소스> --output <새 빈 경로>`; `research_runs/tep_original_reconstruction/PLAN.json`과 `RESULT.json`에 seed·설정·원시 해시·제한을 기록했다. 데이터 `datasetTE.csv` SHA-256은 `52ae445b4355201db9591822282381c8de861afe49bdbc9452db08b01e7d3711`이다. 새 31변수 비교는 시계와 단위가 잠정인 기술 진단이다.

다음 우선 작업은 **TEP Studio를 컴파일할 수 있는 격리된 C 빌드 환경 확보 후, 위 일치한 C 소스·Mode1 초기 상태와 제어기 설정을 고정해 짧은 정상 운전을 실행하고 원본 모델과의 controller/clock 차이를 기록하는 것**이다. 이를 해도 raw Manca 생성 계보와 관측 GT 검증이 없으면 연구 준비 완료가 아니다. 공식 MATLAB 환경과 원시 정상 ZIP·seed·export 자료를 확보할 수 있다면 직접 복원이 더 강한 경로다.

기록 행의 초는 적분된 상태의 시계다. 센서 cache는 한 단계 앞선 평가값이므로 단계 1 이후 센서 시각은 상태보다 1초 빠르다. 분포 분위수·상관은 해당 시계 차이와 짧은 과도 구간을 고려한 기술 기록이다.
