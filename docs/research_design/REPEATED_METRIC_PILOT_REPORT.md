## 3. 네 과제와 실제 조작 가능성

| 과제 | 조작 | 결과 | 목표 평균 | 핵심 방향 경로 |
|---|---|---|---:|---|
| A_Y | A | Y | 1.5 | A→M→Y |
| A_M | A | M | 1.5 | A→M |
| R_Y | R | Y | 3.5 | R→Y 및 R→A→M→Y |
| M_Y | M | Y | 1.0 | M→Y |

모든 과제의 후보는 −1/−0.5/0/0.5/1, 기준 조작은 0, 비용은 0.2×조작²이다. 목표는 예측한 **결과 평균**과 목표의 제곱 차이에 비용을 더한 값을 최소화하는 것이다. 동률이면 작은 절댓값, 이후 작은 조작값을 선택한다. 값들은 무차원이며 물리적 허용·안전 범위가 아니다.

새 API acceptance에서 두 잡음군의 A/R/M에 각각 −0.5와 +0.5를 실제 적용했다. 원본 `intervene_on`/`interventional_sample`이 해당 구조방정식을 상수로 바꾸고, 부모와 해당 외생 잡음 호출을 제거하며, 나머지 식을 보존하는지 확인했다. 12개 조건 각각 48표본을 생성하고 새 객체 동일 seed 반복 및 hook 없는 대조도 exact였다. 관측과 do의 원시 잡음으로 모든 식을 재구성했다. 이번에도 행별 잡음 정렬이나 개인 반사실 추론을 가정하지 않는다.

기준 do(X=0)은 관측 상태에서 아무 것도 하지 않는 것과 다른 정책이다. 여기의 “기준”은 사전 선언된 고정 조작 정책을 뜻한다. 실제 고장·복구 시간·안전 임계값은 없으며 Recovery/Safety 점수를 계산하지 않았다.

## 4. 미확정 방향 정책을 어떻게 구분했는가

1. **확정 간선 전용(기본)**: 기존 코드와 같은 부모 구조를 쓴다. 확정된 Action→Target 경로가 없으면 `NO_PATH_BASELINE_FALLBACK`으로 기준값을 선택한다. 계산해 0을 고른 `COMPUTED_BASELINE`과 구분한다.
2. **동치류 minimax**: 기존 skeleton·확정 방향을 보존하고, 방향 순환과 새로운 비차폐 충돌 구조를 금지한 모든 일관된 DAG 확장을 열거한다. 최대 6개의 미확정 쌍만 지원하며 원래 tail-tail/tail-arrow 의미를 지원하지 못하면 실패 처리한다. 정답 간선·과제 정답 경로를 이 함수에 입력하지 않는다. 각 후보 DAG를 같은 alpha와 데이터로 적합한 후, 후보별 예측 목적값 중 최악값이 가장 작은 조작을 고른다.
3. **추천 불일치 시 보류**: 같은 DAG 확장들이 고른 최적 조작이 서로 다르면 `AMBIGUITY_ABSTENTION`으로 기준값을 유지한다. 모두 일치하면 그 계산 결과를 사용한다. 모든 확장에 경로가 없는 경우는 경로 부재 대체로 별도 기록한다.

구현 기준인 skeleton·비차폐 충돌 구조 일치는 [pgmpy 공식 DAG 문서](https://pgmpy.org/api/generated/base/pgmpy.base.DAG.html)의 관측 동치 설명과 대조했다. 작은 그래프에서 방향 비트 열거 결과를 독립적인 노드 순열 열거와 비교하는 테스트를 통과했다. 후보 DAG를 원래 알고리즘의 최종 그래프로 승격하거나 GT에 맞춰 고르지 않았다. 원래 그래프의 구조 지표는 세 정책에서 동일하게 유지했다. 동치류는 조건부 독립 제약에 따른 후보 집합이며, 모든 후보의 선형 비정규 오차 독립성까지 검증했다는 뜻은 아니다. 표시한 단일 예측은 후보들의 단순 산술평균으로, 사후확률 가중 예측이 아니다. minimax 선택에는 평균 대신 최악 목적값을 사용했다. 예측 범위는 후보 모델들의 범위이며 보장된 신뢰구간이나 물리적 안전성 보장은 아니다.

이번 36개 그래프의 일관된 확장 수는 1개인 그래프 13개, 2개 8개, 3개 11개, 4개 2개, 10개 2개였다. 모든 대안 정책을 실행할 수 있었으며 비지원 구조 실패는 없었다.

## 6. 추천을 고정한 후 실제로 평가한 결과

모든 학습·검증·432개 추천을 마친 뒤 추천 JSON을 SHA `428103859aaa4a91c5567f03ba1733be8530daad799fb7e5ee5daa310d579f6e`로 동결했다. 그 후에만 최종 do 평가를 생성했다. 두 잡음군×3개 Action×(5후보+독립 기준)×3seed×512=**55,296개 표본**이다. A를 조작한 표본은 A_Y/A_M에서 공유하며 같은 값을 고른 모든 그래프·정책도 같은 평가 결과를 쓴다. 중복 생성이나 독립 표본 수 부풀리기는 없다.

평가 항목은 평균·SE·95% 정규근사 구간, 목표 차이, 비용, 목표 평균 손실, 최선 격자 후보 대비 추가 손실, 독립 기준 대비 평균 효과와 예측 오차다. 같은 기준 조작끼리도 다른 독립 seed의 평균 차이가 남을 수 있으며 이는 Monte Carlo 오차다. `(E[결과]−목표)²`와 `E[(결과−목표)²]`는 다르다. 이번 목적은 전자이며 개별 표본의 제곱오차 평균으로 바꾸지 않았다.

과제 간 규모를 맞추기 위해 아래 **상대 추가 손실**을 사전에 정의했다.

`(선택 후보의 실제 평균 손실−동일 격자의 최선 실제 손실) / max(독립 기준 조작의 평균 손실, 1e−12)`

0은 그 평가 격자에서 최선 후보와 같은 손실이다. 1을 넘을 수 있고 자르지 않는다. 별도로 기준 대비 개선 가능한 손실 간격을 분모로 한 값도, 분모가 충분할 때만 저장했다. 최선 후보의 사후 평가값은 추천을 바꾸는 데 사용하지 않았다.

| 잡음 | 과제 | 확정 간선 전용 | 동치류 minimax | 불일치 시 보류 |
|---|---|---:|---:|---:|
| 정규 | A_Y | 0.9419 | 0.4121 | 0.9419 |
| 정규 | A_M | 0.9032 | 0.6209 | 0.9032 |
| 정규 | R_Y | 0.9244 | 0.5981 | 0.9249 |
| 정규 | M_Y | 0.2632 | 0.1919 | 0.3493 |
| Uniform | A_Y | 0.6148 | 0.2650 | 0.6148 |
| Uniform | A_M | 0.6565 | 0.5471 | 0.6565 |
| Uniform | R_Y | 0.6489 | 0.3773 | 0.6387 |
| Uniform | M_Y | 0.0806 | 0.0806 | 0.2419 |

각 셀은 6개 데이터×3개 알고리즘의 균형 평균이다. 정규 표에는 가정 불일치 진단 Direct도 포함되므로 정상적인 인과 식별 성능 평균으로 해석하지 않는다. 알고리즘 제외 민감도는 별도 탐색 파일에 있다. 정책·알고리즘·과제를 합쳐 독립 N=432라고 해석하지 않는다.

같은 그래프·과제의 기본 정책과 비교했을 때 minimax는 정규 72셀 중 23셀의 조작을 바꿨고 22셀 개선/1셀 악화, Uniform은 15셀 변경·14개선/1악화였다. 보류 정책은 정규 6셀 변경·0개선/6악화, Uniform 11셀 변경·7개선/4악화였다. 이 셀들도 독립 표본이 아니다. 구조 지표를 그대로 둔 상태에서 정책만 바뀌어 결과가 달라졌으므로, 추천 성능 차이를 모두 그래프 정확도의 차이로 돌릴 수 없다. minimax가 항상 좋거나 보류가 안전하다는 주장도 하지 않는다.

명시된 식으로 계산한 이론 평균은 학습·추천이 끝난 후에만 실제 평균을 검산하는 데 썼다. 행별 do 식 재구성이 일치했으며, 표본 평균과 이론 평균의 차이는 따로 저장했다. oracle 간선·효과를 학습/선택에 전달하지 않았다.

## 7. 어떤 지표를 정량적으로 탐색할 수 있었는가

독립 단위는 **학습 데이터 12개**, 잡음군별 6개, 잡음×표본 수별 3개다. 각 데이터의 알고리즘 3개·과제 4개·정책 3개는 상관된 반복 관측이다. 평가 표본은 평균 추정의 정밀도를 높일 뿐 독립 그래프 수를 늘리지 않는다.

사전 계획상 탐색 Spearman은 잡음·과제·정책별 데이터 cluster가 최소 6개, 지표·결과가 각각 최소 3개 다른 값일 때만 계산했다. 지표가 0/1 두 값뿐인 경우 해당 상관 비교를 하지 않고 조건별 그룹 평균을 별도로 제시했다. 표본 수별 층에서는 데이터가 3개뿐이어서 이 규칙을 충족하지 못했다. 한 데이터의 모든 알고리즘 행을 함께 제외하는 민감도 범위를 계산했지만 이를 신뢰구간으로 부르지 않는다. p-value나 확정 순위는 없다.

기본 정책 R_Y의 탐색 결과는 다음과 같다. ρ가 음수면 높은 품질과 작은 상대 추가 손실이 함께 나타난 것이다.

| 잡음 | 지표 | 탐색 ρ | 데이터 1개씩 제외한 범위 |
|---|---|---:|---|
| 정규¹ | 연결 F1 | −0.400 | [−0.547, −0.295] |
| 정규¹ | 엄격한 방향 F1 | −0.841 | [−0.853, −0.837] |
| 정규¹ | 핵심 경로 간선 recall | −0.935 | [−0.990, −0.925] |
| Uniform | 연결 F1 | −0.053 | [−0.239, 0.026] |
| Uniform | 엄격한 방향 F1 | −0.638 | [−0.717, −0.602] |
| Uniform | 핵심 경로 간선 recall | −0.668 | [−0.754, −0.629] |

¹ Direct 가정 불일치를 포함한 전체 알고리즘의 진단적 합계다. 이 표는 해당 과제의 **탐색적 연관**이며 지표 우월성이나 지표를 높였을 때 성능이 개선된다는 인과 효과가 아니다. 방향·경로·알고리즘·미확정 비율·밀도가 함께 변하고 있어 효과를 분리하지 못했다.

A_Y/A_M 기본 정책에서는 실제로 선택한 값이 대부분 0 또는 0.5여서 결과 변동이 사전 기준을 충족하지 못했다. M_Y도 Uniform에서는 결과 변동이 부족했다. 전체 분석 파일에는 이처럼 계산할 수 없는 이유를 포함한 1,848개 지표/층/정책 기록을 남겼다. 150개는 탐색 계산 가능, 828개는 지표 변동 부족, 321개는 결과 변동 부족, 549개는 독립 데이터 cluster 부족이었다. 이 개수는 독립 가설 수가 아니다.

Uniform BOSS는 6개 데이터에서 구조 지표가 같아 그 알고리즘 내부에서 해당 품질 변화의 설명력을 확인할 수 없었다. 경로 완전 복원과 직접 XY 정확도 같은 이진 지표에는 이번 연속/다값 상관의 최소 변동 기준이 맞지 않으므로 `analysis_v1/path_groups.*` 등 기술 통계로 제한했다. 이를 효과가 없다는 결과로 바꾸지 않는다.

## 8. 첫 실험의 우연한 좋은 추천은 반복됐는가

정규 Direct의 `gaussian_n256_r2`와 `gaussian_n512_r1`은 A_Y의 직접 관계를 틀렸음에도 A=0.5를 선택해 실제 격자 최선 손실을 얻었다. 엄격한 방향 F1은 각각 0.2와 0.4다. 같은 조건의 올바른 인과 식별이라고 해석하지 않는다. Uniform 기본 정책에서는 “직접 관계 오류인데 최선 조작” 사례가 없었다. 두 잡음군이나 과제를 합쳐 일반화할 수 없는 작은 반복 관찰이다.

전체 연결 F1이 높다고 항상 추천이 좋지는 않았고, 핵심 경로가 맞는 경우와 추천 성능의 관계도 모든 과제에서 통계적으로 비교할 만큼 변하지는 않았다. 특히 기본값 대체·계산된 기본값·불확실성 보류를 구분하지 않으면 잘못된 설명을 만들 수 있다.

## 9. 계산 비용, 실패와 재현 가능한 범위

첫 사전 지정 작은 셀은 3개 학습과 추천 준비에 약 2.563초, 전체 새 실행은 약 42.523초였다. 그래프 학습 기록 시간의 합은 약 28.590초다. 36회 학습·대안 정책·API에서 기록된 실패는 0건이다. 실행 경고인 BOSS의 공분산 BIC 전달 메시지는 원시 console에 보존했다. 계산상 더 큰 반복은 가능하지만 이번 실행에서 반복 수를 늘리지 않았다. 새 seed와 평가 조건은 후속 계획에서 먼저 정해야 한다.

API 동일 seed 반복과 hook 없는 대조는 실제 실행했다. 36개 그래프의 전체 재학습 replay는 **NOT_RUN**이며 같은 seed 반복을 독립 학습으로 세지 않았다. 저장된 모든 관측/do/noise의 식, 추천 재계산, 실제 통계·손실, 동치류 제약, source/환경/계획/파일 SHA를 검증했다. 원본 라이브러리를 사용한 실제 실행과 외부 소스 없는 CI 기록 검사는 다르다.

재현 명령·정확한 lock은 [실행 안내](../../research_runs/repeated_metric_pilot/README.md), 원시 데이터·그래프·모형·고정 추천·432행 표와 탐색 결과는 `research_runs/repeated_metric_pilot/run_v1/`, 읽기 쉬운 요약표는 `analysis_v1/`에 있다. 원시 평가를 그래프별로 복사하지 않았고 외부 모듈·venv·개인 경로 console은 Git에 넣지 않았다. 실행 원시 console과 Git/결과 ZIP은 사용자가 지정한 날짜별 아카이브에 보존한다.

## 10. 현재 답할 수 있는 범위와 다음 실행 조건

**여러 데이터와 과제에서도 지표가 일관되게 설명하는가?** 현재는 일부 과제에서 방향·경로 점수와 손실의 음의 연관을 관찰했지만, 전 과제의 일관성이나 지표 순위를 확정할 근거가 부족하다. 독립 반복이 적고, 상관된 알고리즘/표현 차이와 거친 조작 격자로 변동이 제한된다. 사전 운영상 공식 추론의 최소조건인 잡음×표본 수별 10개 데이터에도 못 미친다. 이 숫자는 검정력 계산으로 얻은 표본 수나 충분성을 보장하는 기준이 아니다.

다음 구현·실행 우선순위는 다음과 같다.

1. **새 독립 seed와 정밀도 계약을 고정한 반복 확대**: 필요한 유효 graph-fit cluster 수와 사전 예측 비교 모형·평가 단위를 정한다. 현재 결과로 유리한 seed만 추가하지 않는다. 확인용 평가 자료는 기존 55,296개를 새 미사용 데이터라고 재사용하지 않는다.
2. **정책 차이와 구조 차이의 분리**: 같은 그래프에서 세 정책의 paired 차이를 유지하고, 표현·밀도·알고리즘별 조건을 맞춘 비교와 학습 데이터 단위 holdout을 설계한다. 지표 사이 공선성을 확인하기 전 설명력 1위를 고르지 않는다.
3. **과제/후보 격자의 변동성 계약**: 목표·비용/후보 변경은 새 사전 계획으로 분리한다. 같은 구조에서 여러 목표를 만든 것을 독립 구조 표본으로 세지 않고, 과제 family를 보존한다.

이 단계까지는 기존 연구 질문을 유지한 인공 데이터 탐색이다. TEP 제조공정의 직접 가설 검증, Fault 복구, 안전성, 엄격한 개인 반사실 추론, Track B 제조환경 채택은 여전히 완료되지 않았다.
